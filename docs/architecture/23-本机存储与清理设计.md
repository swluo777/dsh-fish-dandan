# 23 · 本机存储与清理设计

## 为什么做

`data/` 是运行时目录，里面最占空间的不是代码，而是浏览器档案、表情包和形象原图。审计时本机 `data` 约 2.1GB，其中：

| 分类 | 审计时占用 | 说明 |
|------|-----------|------|
| 浏览器档案 | 约 1.45GB | `browser-profile` 约 900MB；旧版遗留 `browser-profile-listen` 约 549MB |
| 表情包 | 578.9MB | 用户已确认不瘦身 |
| 形象原图 | 73.8MB | 13 张 2848×1600 PNG，可选运行数据 |
| 模板 / 其他 | 约 6MB | 文字卡片底图、记忆、状态、日志等 |

浏览器缓存会越用越大，但它是可再生的；旧监听档案是历史遗留，当前共享浏览器已经不再使用。所以第一版只处理这两类，不碰用户真正在乎的数据。

## 清理边界

### 允许清理

只清共享档案 `data/browser-profile` 里的：

- `Default/Cache`
- `Default/Code Cache`
- `Default/GPUCache`
- `Default/DawnCache`
- `Default/DawnGraphiteCache`
- `Default/DawnWebGPUCache`
- `Default/ShaderCache`
- `component_crx_cache`
- `ProvenanceData`

以及整个旧监听档案 `data/browser-profile-listen`。

### 绝对不删

- `Default/Cookies`（实际在 `Default/Network/Cookies`）
- `Default/Login Data`
- `Default/Preferences`
- `Local State`
- `Default/Network/Network Persistent State`
- `Default/Sessions`
- 人格、记忆、状态、模板、表情包、形象原图

`browser-profile` 不能整目录删。整目录删会连同登录态、站点数据和本地存储一起删掉，用户下次打开抖音就得重新扫码。

### 浏览器占用

缓存文件可能被正在运行的 Edge 占用。清理遇到 `EBUSY / EPERM / EACCES / ENOTEMPTY` 时返回“有文件被占用，先关闭 DSH 浏览器”，不静默跳过成功。正常流程不主动强杀浏览器。

## 后端

新增 `src/storage/index.js`：

- `summary()`：扫描 `data` 顶层，返回总占用、分类、两个档案状态、可清理项和一句安全说明。
- `clean({ targets })`：只接受 `cache` 和 `legacy`；逐项删除并返回 `freedBytes / results / errors / after`。
- 缓存白名单是常量，不从请求参数接收路径；`safeInside()` 防止清理路径越出 `data`。
- 跳过符号链接，避免统计或清理到目录外。

新增 API：

- `GET /storage`：返回存储摘要。
- `POST /storage/cleanup`：请求体 `{ targets: ["cache", "legacy"] }`；未知 target 返回 400 `TARGETS_INVALID`。
- 部分清理失败时返回 200 + `partial: true` + `errors`，前端可提示“已释放多少、几项被占用”。

## 网页

左侧导航在“表情包”后、“安全”前新增“存储”。

页面分三块：

1. **总览**：总占用、可清缓存、旧监听档案、形象原图；右上角“清理存储”。
2. **可清理**：两项的当前大小和说明；不可用时置灰。
3. **占用明细**：浏览器档案、表情包、形象原图、模板底图、其他，带占比条。

“清理存储”打开小弹窗，只有两个复选项：

- 清理可再生缓存
- 清理旧监听档案

弹窗固定提示：“只清可再生文件，不动登录态、人格、记忆、形象原图和表情包。”按钮为“取消 / 开始清理”。清理中按钮禁用，完成或部分失败都有 toast；页面重新拉取摘要。

## 实测

本轮一次性清理：

- 共享档案可再生缓存：770.46MB / 1976 文件
- 旧监听档案：549.10MB / 2186 文件
- 合计释放约 1,319.56MB
- 共享档案从 900.24MB 降到 129.78MB
- Cookies、Login Data、Preferences、Local State、Network Persistent State 哈希复核未变
- `Default/Sessions` 访问被拒绝但文件仍在，未列入删除目标

清理后 `data` 分项约 0.8GB；形象原图曾因用户测试删除而暂时为空，随后用项目下载器从 GitHub Release 恢复 13/13，总字节 `77,393,766`，SHA-256 全部通过。当前 `data` 约 788.5MB。

## 还没做

- 缓存容量上限和 `--disk-cache-size` 启动参数
- 定期自动清理策略
- 日志轮转
- 表情包瘦身 / LRU
- 删除本机形象原图的二次确认页（当前用浏览器 confirm）

这些都留到后续，不和第一版“只清两项”混在一起。
