# 23 · 本机存储与清理设计

## 为什么做

`data/` 是运行时目录，里面最占空间的不是代码，而是浏览器档案、表情包和形象原图。2026-11-15 审计时本机 `data` 约 1537.8MB，其中：

| 分类 | 审计时占用 | 说明 |
|------|-----------|------|
| 浏览器档案 | 约 874.3MB | `browser-profile` 约 834MB；旧监听档案当前不存在 |
| 表情包 | 约 607.2MB | 用户已确认不瘦身 |
| 形象原图 | 约 77.4MB | 13 张 2848×1600 PNG，可选运行数据 |
| 创作相关 | 约 46.7MB | `data/creative` 44.55MB + `data/images` 等 |
| 模板 / 其他 | 约 7MB | 文字卡片底图、记忆、状态、日志等 |

浏览器缓存会越用越大，但它是可再生的；旧监听档案是历史遗留，当前共享浏览器已经不再使用；自由创作会不断留下 HTML 旧稿，旧版宿主还留下过导出目录和任务目录。存储页按“创意工作室 / 自由创作 / 旧版残留 / 其他”分开看，只清可以再生的部分。

## 清理边界

### 允许清理

只清共享档案 `data/browser-profile` 里的：

- `Default/Cache`
- `Default/Code Cache`
- `Default/GPUCache`
- `Default/DawnCache`
- `Default/DawnGraphiteCache`
- `Default/DawnWebGPUCache`
- `ShaderCache`
- `GrShaderCache`
- `component_crx_cache`
- `ProvenanceData`

以及整个旧监听档案 `data/browser-profile-listen`。

自由创作相关只清：

- `data/creative/creative-*.html` 中最近 15 张以外的旧稿
- `data/creative/exports/`、`data/creative/jobs/`、`data/creative/runtime/` 里的旧版宿主残留
- `data/creative/inputs/` 里的渲染临时参数
- `data/images/` 下 `ui-fail-*` 失败截图

只清旧稿时同步原子改写 `data/creative/index.json`，不留下“索引指向已删 HTML”的坏状态；桌面 PNG 不动。

### 创意工作室边界

创意工作室的作品由插件自己管理，当前实际输出在插件目录 `data/exports/<job_id>/`。宿主存储页只读展示当前作品的大小与只读状态，不提供删除按钮，也不替插件决定输出目录或清理策略。宿主只管理 `data/creative/account/`（账号头像）和 `data/creative/inputs/`（渲染输入）这类宿主自己产生的文件。

### 绝对不删

- `Default/Cookies`（实际在 `Default/Network/Cookies`）
- `Default/Login Data`
- `Default/Preferences`
- `Local State`
- `Default/Network/Network Persistent State`
- `Default/Sessions`
- 人格、记忆、状态、模板、表情包、形象原图
- 创意工作室当前作品、账号头像
- 自由创作最近 15 张稿子、桌面 PNG
- 豆包生图（`data/images` 里非 `ui-fail-*` 的图片）

`browser-profile` 不能整目录删。整目录删会连同登录态、站点数据和本地存储一起删掉，用户下次打开抖音就得重新扫码。

### 浏览器占用

缓存文件可能被正在运行的 Edge 占用。清理遇到 `EBUSY / EPERM / EACCES / ENOTEMPTY` 时返回“有文件被占用，先关闭 DSH 浏览器”，不静默跳过成功。正常流程不主动强杀浏览器。

## 后端

新增 `src/storage/index.js`：

- `summary()`：扫描 `data` 顶层，返回总占用、分类、两个档案状态、三类可清理项和一句安全说明；创作再拆成 `creative-studio`、`creative-free`、`creative-legacy`。
- `clean({ targets })`：接受 `cache`、`legacy`、`free-drafts`；逐项删除并返回 `freedBytes / results / errors / after`。
- `free-drafts` 只清最近 15 张以外的自由创作 HTML，同步收敛 `index.json`；同时清旧版宿主残留、渲染临时参数和 `ui-fail-*` 失败截图。
- 清理旧稿前通过 `getCreativeStudio()` 检查 `status().run / action.busy / runtime.installing`；正在创作或安装依赖时返回 409 `CREATIVE_BUSY`。
- 缓存白名单是常量，不从请求参数接收路径；`safeInside()` 防止清理路径越出 `data`。
- 跳过符号链接，避免统计或清理到目录外。
- `src/creative/renderer.js` 在渲染结束的 `finally` 里删掉本次 `data/creative/inputs/<job_id>/`，新任务不再堆积临时参数。

新增 API：

- `GET /storage`：返回存储摘要。
- `POST /storage/cleanup`：请求体 `{ targets: ["cache", "legacy", "free-drafts"] }`；未知 target 返回 400 `TARGETS_INVALID`。
- 部分清理失败时返回 200 + `partial: true` + `errors`，前端可提示“已释放多少、几项被占用”。

## 网页

左侧导航在“表情包”后、“安全”前新增“存储”。

页面分三块：

1. **总览**：总占用、可清缓存、旧监听档案、创作旧稿、形象原图；右上角“清理存储”。
2. **可清理**：三项的当前大小和说明；不可用时置灰。
3. **占用明细**：浏览器档案、表情包、形象原图、模板底图、创意工作室、自由创作 / 画画、旧版创作残留、插件与运行环境、其他，带占比条。

“清理存储”打开小弹窗，只有三个复选项：

- 清理可再生缓存
- 清理旧监听档案
- 清理自由创作的旧稿

第三项默认不勾选，必须手动勾选才执行；保留最近 15 张自由创作 HTML，同时清旧版残留、渲染临时参数和失败截图。弹窗固定提示：“不会删除登录态、人格、记忆、形象原图、表情包、当前创作作品、账号头像和豆包生图。”按钮为“取消 / 开始清理”。清理中按钮禁用，完成或部分失败都有 toast；页面重新拉取摘要。

## 历史实测

旧监听档案一次性清理：

- 共享档案可再生缓存：770.46MB / 1976 文件
- 旧监听档案：549.10MB / 2186 文件
- 合计释放约 1,319.56MB
- Cookies、Login Data、Preferences、Local State、Network Persistent State 哈希复核未变
- `Default/Sessions` 访问被拒绝但文件仍在，未列入删除目标
