# 主页「当前状态」：情感模型调研与选型

> 需求：主页要能一眼看出大肥鱼的**性格状态、情绪状态、心情**，并且不能凭主观想象设计，要有游戏 / 虚拟角色领域的现成方案作依据。
> 结论：采用 **ALMA 三层情感模型**（Personality / Mood / Emotion），落地在 `src/decision/affect.js`，接口为 `/overview.affect` 与 `/decision.affect`。

## 一、调研到的现成方案

| 项目 / 文献 | 关键做法 | 我们吸收了什么 |
|---|---|---|
| **ALMA**（A Layered Model of Affect, Gebhard 2005） | 把情感按时间尺度分三层：人格（长期）、心情（中期，不绑定具体事件）、情绪（短期，绑定事件、快速衰减） | 主页三张卡的结构；三层的命名与时间尺度 |
| **VirtualHuman / Gebhard**（OCC + FFM + PAD） | Big Five 五维全部用于偏置情绪强度与衰减率；心情用 PAD 三维；心情八分体（+P+A+D 兴高采烈、−P−A−D 无聊、−P+A−D 焦虑…） | 八分体中文命名；「人格影响情绪强度与衰减」 |
| **Mehrabian Big Five → PAD 转换**（ALMA / MDPI Electronics 2026, 15(8):1691 引用） | 用线性组合把 OCEAN 映射成 P/A/D 基线 | `personalityToPad()` 的三条线性公式 |
| **Russell 环状情绪模型** | 情绪用 valence（愉快/不快）× arousal（兴奋/平静）二维坐标表示 | 主页的情绪环状图 |
| **OCC 评价模型**（Ortony / Clore / Collins） | 事件经「合意性 desirability、可赞性 praiseworthiness、可能性 likelihood、归因 agency」评价后触发离散情绪 | `EVENT_APPRAISALS` 事件模板；`appraise()` |
| [ashina814/census](https://github.com/ashina814/census)（Minecraft 村民） | 每个角色有 Big Five 人格 + 8 种 OCC 情绪 + 慢速 PAD 心情 + 记忆反思；**同一事件因人格不同产生不同情绪**；游戏内 HUD 展示 | 人格调制负性情绪；主页 HUD 的信息组织 |
| [lucylow/quaternion](https://github.com/lucylow/quaternion) Generative NPCs | OCEAN 原型（archetype）+ 24 种情绪 + Mood 聚合近期情绪 + 关系系统；neuroticism 放大负性情绪 | 配置向导的四个 OCEAN 原型；情绪表 |
| [GAMYGDALA](https://github.com/prbarcelon/Gamygdala.Net) | 面向游戏 NPC 的 OCC 评价引擎，输出离散情绪 + PAD 向量，带指数衰减与人格基线 | 指数衰减与「默认情绪状态＝人格基线」 |
| [Pavel6625/PaulusAI](https://github.com/Pavel6625/PaulusAI) | 可落地的数值方案：PAD∈[−1,1]、16 情绪表、事件评价模板、`reactivity=0.7`、负性情绪按 `0.7+0.6×neuroticism` 放大、情绪 PAD 签名 ×0.5 汇入心情、每轮向基线回归 15% | `appraise()` 的强度公式；心情汇入与回归 |
| [wiebe-xyz/github-tamagotchi](https://github.com/wiebe-xyz/github-tamagotchi) | 五个性格特质**不只是文案**，用 clamped linear interpolation 真实缩放心情阈值（tidiness→脏乱、bravery→担忧、sociability→孤独…） | `deriveThresholds()`：性格真实喂给状态机 |

**影响状态的因素**（综合上述项目）：事件评价（合意性 / 可赞性 / 可能性 / 归因）、目标一致性、人格调制、时间衰减、社交关系、生理需求（精力 / 无聊 / 昼夜节律）、记忆反思。主页「是什么在影响它」折叠区把这些逐项列出，且每一项都对应真实计算，不是装饰文案。

## 二、本项目的落地

```
persona.personality.traits (Big Five, 1..10)
        │  personalityToPad()          Mehrabian 线性转换
        ▼
   PAD 人格基线 ──────────────────► deriveThresholds()
        │                            (explore/social/create/sleep 阈值、
        │                             negativeGain、decayFactor)
        ▼                                    │
   心情 Mood (P/A/D ∈ [−1,1])               ▼
        ▲   情绪 PAD 签名加权趋近      nextState() 真实使用
        │   （单步最多挪 0.22，防饱和）
   情绪 Emotion（8 种，指数衰减）
        ▲
   事件评价 OCC（状态切换 / 自主决策 / 平台消息 / 人工确认 / 生理需求）
```

- **性格**：沿用项目已有的 Big Five 五维（`persona/default-persona.json`），不新增第二套性格数据。
- **心情**：`baseline` 来自人格；八分体给中文名；`history` 保留最近 48 次采样供趋势图使用。
- **情绪**：8 种（开心 / 安心 / 好奇 / 惊讶 / 无聊 / 焦虑 / 低落 / 烦躁），各有 valence、arousal、PAD 签名、衰减半衰期；事件模板 14 种。
- **真的接进状态机**：`deriveThresholds()` 的输出通过 `nextState(..., { thresholds })` 注入，`ENTER` 阈值改为可配置；不传阈值时保持原数值，因此既有 14 项状态机测试全部不变。这解决了原实现里 `mood` 变量「只算不用」的问题。
- **持久化**：`data/state/affect.json`，`normalizeAffect()` 对脏数据容错；写盘与状态快照共用 `writeJsonAtomic()`。

## 三、为什么不用其它方案

| 方案 | 不采用的原因 |
|---|---|
| 只做 valence × arousal 二维情绪坐标 | 缺少「性格如何影响状态」这一层，主页会变成纯展示，性格五维与状态机仍然零耦合 |
| 沿用原五变量进度条，只美化 | 五个量都是 0–100 的需求值，没有情绪与心情的概念，答不出「它现在心情怎么样」 |
| 引入 LLM 实时生成情绪 | 需要外部请求与逐轮推理，违背本项目「零外部请求、本地可复现」的约束，且不可单测 |
| 24 种 / OCC 全 22 种情绪 | 小尺寸图表放不下，用户也读不过来；8 种覆盖主要象限，符合渐进式披露 |

## 四、前端技术选型

用户提出可用 Remotion / Three.js 等。经评估**都不引入**：

- **Remotion** 是用 React 渲染 mp4 的框架，不是网页 UI 运行时，需要 Node 构建与 ffmpeg，与本场景无关。
- **Three.js** 需要 WebGL 与约 600 KB 运行时；本项目是单 `index.html`、无构建工具、宿主本地 HTTP 服务、`nosniff` + 回环限制、零外部请求，引入会破坏架构并带来 webview 兼容风险。

改为**原生 SVG + CSS + Canvas 2D**：雷达图、Russell 情绪环、PAD 仪表、趋势折线全部手写 SVG；呼吸光晕、浮动、路径绘制用 CSS `@keyframes`；气泡用 Canvas 2D（22 个粒子、`requestAnimationFrame`、离开页面即停止）。视觉层次、动效、深浅主题与 `prefers-reduced-motion` 降级都不依赖任何外部资源，且有 `test/web.test.js` 做静态冒烟保护。

## 五、已知边界

- 情绪由插件内部事件触发；**对话内容本身不会自动写入记忆或情绪**（当前没有会话内容的事件源），主页「这一版还做不到的」已如实写明。
- 趋势曲线需要积累采样点，全新安装时显示「还在攒数据」，不是伪造的演示曲线。
- 心情八分体与情绪表是工程化简化，不是心理学测量工具；数值用于让行为有连续性与可解释性。
