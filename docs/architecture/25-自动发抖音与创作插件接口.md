# 25 · 自动发抖音与创作插件接口

> 状态：第二阶段（2026-11-15）
>
> 本轮做了：侧边栏入口、创作插件只读发现、本地目录登记、单安装槽卸载、独立 Python 运行环境、心情参数生成、`render-job` 渲染、页面创作状态，以及**完整图文自动发布**（发布图文 → 上传当前作品 → 标题/正文 → 推荐第一首音乐 → 发布）。
> **GitHub 安装器已接入；自动发布走共享浏览器的登录档案。本地安装只登记目录，不复制文件；GitHub 安装浅克隆到平台插件目录；依赖目录统一放在插件同级的 `<插件目录名>-runtime`，不改用户项目，也不进宿主 Git。**

## 1. 这一阶段做到哪

自动发抖音不是把发布脚本重新接回来，而是把另一套独立项目接成一个可安装的创作插件：

- 独立项目：`dandan-creative-studio`（本地开发目录 `E:\Projects\dandan-creative-studio`）。
- 它负责：内容计划、Pillow 渲染、质检、发布包与发布队列。
- 当前能力：`image_post` 的 `black-card` 版式，输出 1080×1440 PNG。
- 当前没有：HTTP API、宿主参数网关；**GitHub 安装器由宿主实现，不在插件仓库里执行**。
- 它的真实抖音发布也还没实现，`DouyinPublisher` 目前只做 dry-run。
- **边界：宿主只负责安装权限、参数生成和调用；参数怎么变模板、图文落到哪个目录、以后怎么发布，都由创作工作室自己的链路决定。**

所以宿主侧负责“怎么发现它、怎么安装、怎么给参数、怎么渲染、按钮什么时候可用、怎么把当前作品发出去”；创作工作室负责内容计划和渲染，抖音发布走宿主共享浏览器的登录档案。

## 2. 页面与入口

- 左侧导航新增 **自动发抖音**，放在 **平台** 之后、**表情包** 之前。
- 页面现在分成：Hero、创作工作室（安装与准备）、创作卡（自动做图文 + 当前作品渐进披露）、发布卡（自动发布 + 图文/画画参数 + 全自动占位）。
- 创作卡只保留 **自动做图文** 一个主按钮；完成后 **当前作品** 收进创作卡内的折叠行，展开后显示图片、主题/姿势、配文、作品目录和放大入口，不再单独占一张大卡片。
- 发布卡提供参数：
  - **图文** 默认勾选；发“当前作品”里的那张图。没有当前作品时提示“当前没有作品，先做一张图文”，不打开浏览器。
  - **画画** 目前灰色禁用，参数“画几张”默认 1、最多 10，接“专注创作”留到后续阶段。
  - **全自动发抖音** 目前灰色禁用，等发布链路稳定后再做定时/自动策略。
- **自动发布** 已接通完整图文链路：用共享浏览器固定档案打开 `creator.douyin.com/creator-micro/content/upload` → 点“发布图文” → 上传当前作品 → 填作品标题（当前作品短配文）和描述（图里的 hook + body）→ 下方“选择音乐”打开推荐侧栏 → 鼠标悬停第一首推荐、点出现的“使用” → 滚到底部点“发布”。失败时标签页停在当前步骤，不静默重试；页面只给可读原因。
- 两个主按钮未就绪时都是**灰色锁定态**；未安装提示 **“先安装创作工作室”**，安装不完整、能力不匹配、环境依赖没装好时也分别给明确提示。只有 **插件安装 + 环境依赖就绪 + 文案模型就绪** 时才恢复主按钮样式。
- 创作工作室卡常驻显示，按状态切换内容：
  - **未安装**：显示“还没有安装”，主按钮 **从 GitHub 安装**；右侧箭头菜单里同时提供 **从 GitHub 安装** 和 **从本地安装**。
  - **安装不完整**：显示“安装不完整”，提供卸载后重装。
  - **已安装但环境依赖没装好**：显示“插件”行和“环境依赖”块。Python 行提供 **检测本机 Python**，优先使用 DSH 自带的 Python；只有它不可用时才需要用户自己安装。依赖行提供 **安装依赖**，只有检测到可用 Python 后才可点。首次安装依赖期间显示进度条。
  - **已安装且环境依赖就绪**：仍保留创作工作室卡，用“插件”和“环境依赖”两行展示；环境依赖块显示两个绿点，分别是 **Python 已装好** 的路径和 **依赖已装好** 的目录，卸载入口固定在插件行右侧。
- 创作中按钮显示“创作中…”，完成后在创作卡内展开 **当前作品** 折叠行：左侧图片，右侧主题、角色、配文和“复制配文”；不保留单独的“再做一张”按钮，用户直接再点一次 **自动做图文** 即可生成下一张。不展示 QA 或内部 job 信息；图片不可预览时收起图片位，给出“预览不在了，再点一次自动做图文”的可读提示。
- 失败时只给用户可读结果，不把后端错误码、Python/依赖名、插件路径直接写到页面上。

侧边栏入口始终显示。即使插件没装，也能看到入口和安装边界，不会出现“功能藏在某个开关后面找不到”的情况。

## 3. 插件契约（宿主侧 v0）

### 3.1 安装位置

```text
data/plugins/dandan-creative-studio/          # GitHub / 复制安装的固定目标目录
data/plugins/dandan-creative-studio-runtime/  # 依赖 venv，与插件目录同级（GitHub 版示例）
data/state/creative-studio.json               # 安装记录；本地安装和 GitHub 安装都写这里
```

安装记录字段：

```json
{
  "schemaVersion": 1,
  "id": "dandan-creative-studio",
  "source": "local | github",
  "managed": false,
  "repo": "owner/repo",
  "repository": "https://github.com/owner/repo.git",
  "ref": "main",
  "path": "E:\\Projects\\dandan-creative-studio",
  "version": "0.1.0",
  "installedAt": "2026-11-14T00:00:00.000Z"
}
```

`managed: false` 表示用户自己的本地目录；`managed: true` 表示平台下载到 `data/plugins/` 的副本。本地安装只写记录，不复制项目文件。记录所在目录被 `.gitignore` 覆盖。

### 3.2 识别条件

一个目录会被认作 `dandan-creative-studio`，至少需要：

```text
pyproject.toml                  # [project].name = "dandan-creative-studio"
studio/__main__.py              # python -m studio 入口
studio/pipeline.py              # plan -> renderer 管线
templates/<template>/template.json
```

模板里的 `format` 决定宿主显示的能力；当前只认到 `image_post` 图文。

### 3.3 本地安装

`POST /fish-dandan/api/creative-studio/install-local`，请求体：

```json
{ "path": "E:\\Projects\\dandan-creative-studio" }
```

宿主会：

1. 先检查当前是否已有活跃安装；有就拒绝，要求先卸载。
2. 要求绝对路径，去掉首尾引号。
3. 确认目录存在且确实是目录。
4. 用和固定安装目录同一套契约检查项目名与关键文件。
5. 通过后写 `data/state/creative-studio.json`；状态立即变为 `installed`。
6. 不复制文件、不执行 Python、不改动原目录。

失败码：

- `ALREADY_INSTALLED`（已有活跃安装，必须先卸载）
- `ENV_OVERRIDE`（环境变量开发覆盖占用中，先移除环境变量）
- `PATH_REQUIRED` / `PATH_NOT_ABSOLUTE` / `PATH_NOT_FOUND` / `PATH_NOT_DIR`
- `PLUGIN_INVALID`（项目名不匹配或关键文件缺失）
- `RECORD_WRITE_FAILED`（安装记录写入失败）

### 3.4 从 GitHub 安装

`POST /fish-dandan/api/creative-studio/install-github`，请求体：

```json
{ "repository": "https://github.com/swluo777/dandan-creative-studio.git" }
```

宿主会：

1. 只接受 `https://github.com/<owner>/<repo>` 或 `git@github.com:<owner>/<repo>`，拒绝带账号密码、查询参数和其他域名；默认预填 `https://github.com/swluo777/dandan-creative-studio.git`。
2. 先检查单安装槽；已有本地/GitHub/开发版安装时拒绝，要求先卸载。
3. 先选网络：直连（显式清空 Git 代理）→ 系统代理（仅 Windows 代理开启时）→ 环境变量代理 → Git 全局代理；每个候选先用 `git ls-remote --symref <repo> HEAD` 探测，超时 7 秒就换下一条。选定后执行 `git clone --depth 1 --single-branch --no-tags --progress` 拉到平台插件目录同级的临时目录，不执行仓库里的任何代码；页面在拉取期间显示真实进度（Git 的 `Receiving objects` / `Resolving deltas` / `Updating files` 百分比），状态接口的 `install.progress` 返回 `percent`、`phase`、`detail`。克隆连续 60 秒没有新进度时，会结束当前 Git 进程、清理临时目录并换下一条候选。
4. 页面可以点“取消”：后端结束正在运行的 Git 子进程，清掉临时目录，不写安装记录。浏览器/页面中途关闭时，宿主也会检测到连接断开并取消克隆。
5. 插件启动和每次安装前都会清理 `.dandan-creative-studio-install-*` 残留目录；只清插件目录同级的临时目录，不碰正式插件目录。
6. 用和本地安装同一套契约检查 `pyproject.toml`、`studio/__main__.py`、`studio/pipeline.py` 和模板。
7. 检查通过后整体换入 `data/plugins/dandan-creative-studio`；已有残留目录先备份，失败会恢复，避免半安装。
8. 写安装记录：`source: "github"`、`managed: true`、`repo`、`repository`、`path`、`version`。

失败码：

- `ALREADY_INSTALLED` / `ENV_OVERRIDE`
- `GITHUB_URL_REQUIRED` / `GITHUB_URL_INVALID`
- `GIT_NOT_FOUND` / `GITHUB_TIMEOUT` / `GITHUB_CLONE_FAILED` / `GITHUB_CANCELED`
- `GITHUB_STALLED` / `GITHUB_NETWORK_UNREACHABLE`
- `PLUGIN_INVALID`（仓库不是完整创作工作室）
- `INSTALL_PATH_INVALID` / `RECORD_WRITE_FAILED`

### 3.5 开发副本

开发时也可以用环境变量直接指向本地仓库，优先级高于安装记录，适合临时调试：

```text
FISH_DANDAN_CREATIVE_STUDIO_PATH=E:\Projects\dandan-creative-studio
```

它只影响“发现和显示”，不会执行这个仓库里的任何代码。环境变量属于当前活跃安装，会占用单安装槽；要先移除它才能通过页面安装。

### 3.6 环境依赖

依赖不属于宿主 Node 项目，也不装进全局 Python。边界是：

- `dandan-creative-studio` 在 `pyproject.toml` / `requirements.txt` 里声明 Python 版本和依赖；
- 宿主负责在插件安装后，**为用户显式点击的“安装依赖”创建一个隔离 venv**；Python 本体不自动下载安装。
- 不装创作插件就用不到 Python，平台启动时不做任何 Python 检测或安装。

**环境依赖（两步，都由用户点击）：**

- 页面在“环境依赖”块里提供两个动作：**检测本机 Python** 和 **安装依赖**。
- 用户先点 **检测本机 Python**：页面调用 `POST /fish-dandan/api/creative-studio/detect-python`，只扫描 Python 版本/路径，不下载、不安装、不执行插件代码。检测顺序优先使用 **DSH 自带的 sandbox Python**，再找系统 Python；找到 3.11+ 时显示版本、来源和路径，没找到时再提示手动安装并提供官网下载链接。
- 用户再点 **安装依赖**：只有检测到可用 Python 后才可点。宿主内部创建 venv 并安装插件声明的依赖；安装期间页面只显示统一进度条和“正在安装依赖…”。
- 依赖装好后，“环境依赖”块显示两行，每行一个绿点：**Python 已装好** 及解释器路径，**依赖已装好** 及 venv 目录。
- 页面不展示 `Pillow` / `tzdata` 包名，也不把 Python 扫描过程写成技术日志。

Python 选择顺序（内部实现，和检测同一套）：

- `FISH_DANDAN_CREATIVE_STUDIO_PYTHON` 指定的解释器；
- **DSH 自带 Python**：从 `process.resourcesPath` 或 `process.execPath` 推导 DSH 安装目录，再定位 `<resources>/runtime/primary-runtime/dependencies/python/python.exe`；可用 `DSH_RESOURCES_PATH` 覆盖测试；
- 当前激活的 `VIRTUAL_ENV` / `CONDA_PREFIX`；
- Conda：`~/.conda/environments.txt`、各盘 Anaconda/Miniconda 根目录、`envs/*`、以及 `where.exe conda` 能定位到的安装根；
- 标准 venv：在项目目录、用户目录和常见工程目录里按 `pyvenv.cfg` 做有界扫描，不每次全盘扫；
- Windows `py -0p` 的登记、`where.exe python` / `where.exe python3` 的 PATH 路径；
- `%LOCALAPPDATA%\Programs\Python`、`%ProgramFiles%\Python`、`C:\Python3*` 等常见目录；
- 豆包自己的 sandbox Python：`%LOCALAPPDATA%\Doubao\User Data\sandbox_runtime\bases\*\python\python.exe`，只作兜底，不冒充 DSH 自带 Python。

DSH 自带 Python 作为首选，但只有 3.11+ 且可运行才会被选中；如果它不可用，再回退到当前环境、Conda、venv 或系统 Python。没有 Python 时返回 `PYTHON_NOT_FOUND` / `PYTHON_VERSION_UNSUPPORTED`，页面提示手动安装 Python 3.11+ 并给下载链接；检测接口和安装依赖接口都不自动下载 Python。

环境依赖位置：

```text
data/plugins/dandan-creative-studio-runtime/      # GitHub 版：与插件目录同级，卸载时一起删除
<插件目录的父目录>/<插件目录名>-runtime/           # 本地版：同样与插件目录同级，不写用户项目
```

“安装依赖”流程：

1. 优先使用 `FISH_DANDAN_CREATIVE_STUDIO_PYTHON` 指定的解释器；指定了就只做导入检查，不由平台装依赖。
2. 否则优先使用可运行的 DSH 自带 Python（3.11+），再回退到系统 Python 3.11+；都没有就返回 `PYTHON_NOT_FOUND` / `PYTHON_VERSION_UNSUPPORTED`。
3. 创建或清空平台自己的 venv。
4. 用 venv 里的 pip 安装插件 `requirements.txt` 声明的依赖（当前是 `Pillow`、`tzdata`）。
5. 默认源是 `https://pypi.tuna.tsinghua.edu.cn/simple`；可用 `FISH_DANDAN_CREATIVE_STUDIO_PIP_INDEX` 覆盖。国内源失败时回退一次官方源。
6. 安装期间通过 `runtime.progress` 暴露 `percent` / `message` / `phase`，页面轮询显示进度条。
7. 检查 `PIL`、`zoneinfo.ZoneInfo("Asia/Shanghai")` 可导入，成功后写 `.fish-dandan-ready.json`，记录 `sourcePython` 和 `pythonVersion`。
8. 失败时返回可读错误：`PYTHON_NOT_FOUND`、`PYTHON_VERSION_UNSUPPORTED`、`VENV_CREATE_FAILED`、`PIP_INSTALL_FAILED`、`PYTHON_DEPS_MISSING`。

### 3.7 单安装槽与卸载

同一时间只允许一个活跃安装，不允许多版本并存：

- 安装第二种来源前，必须先卸载当前版本。
- 页面在已安装/安装不完整时不再显示安装入口，只显示“卸载”。

`POST /fish-dandan/api/creative-studio/uninstall`：

- **本地版**：只删除 `data/state/creative-studio.json` 里的登记，把页面还原为“未安装”；**不删除本地插件目录、不删除插件同级的 `<插件目录名>-runtime` 依赖目录、不删除本机 Python**。
- **GitHub 版**：删除 `data/plugins/dandan-creative-studio` 的平台副本和同级的 `data/plugins/dandan-creative-studio-runtime` 依赖目录，再删除安装记录；**不删除本机 Python**。
- 删除 GitHub 副本前校验目标必须在安装目录内，拒绝符号链接、拒绝越界路径。
- GitHub clone 的 `.git/objects/pack/*` 在 Windows 上带只读属性，删除前会递归清掉只读位再删目录，避免 `EPERM` 导致卸载失败；同一套删除逻辑也用于安装临时目录和依赖目录。
- 环境变量覆盖不从页面卸载，提示用户移除环境变量。

失败码：`ENV_OVERRIDE`、`NOT_INSTALLED`、`UNINSTALL_PATH_INVALID`、`UNINSTALL_DELETE_FAILED`、`RECORD_REMOVE_FAILED`。


`runtime.progress` 在准备期间是 `{ percent, message, phase }`；`last` 只保存最近一次结果：`jobId`、`ok`、主题、角色、`caption`、创作工作室返回的输出目录、QA、`recentThemes`/`recentPoses`（最近三张用过的主题和姿势，供下一张避让），以及 `previewable`（图片是否仍在插件目录内、可交给页面预览）；失败时保存错误码和消息。状态接口只扫描目录和 JSON，不执行 pip、不 spawn 渲染。页面不展示 QA、job 等技术字段，只读 `jobId` 取预览图；`previewable: false` 的旧结果按没有作品处理，不迁移旧宿主目录。**唯一例外是“当前作品”下的“作品目录”：它只读展示创作工作室返回的 `outputDir`，并提供复制路径，方便用户去插件自己的目录里找产物；宿主不按这个路径复制或搬移文件。**

视觉参数策略：插件提供的 6 个主题和 5 个姿势全部进入候选池；心情只提高部分候选的权重（基础权重 3，心情加成 1～2），不把候选缩成固定一种。宿主用 `jobId` 派生的确定性种子做加权选择，并避开上一张及最近三张用过的主题和姿势；因此心情稳定时会轮换颜色和姿势。角色位置仍由插件现有姿势映射决定：`stand`/`wave`/`sit` 在右下角，`peek-left`/`peek-right` 在左右边缘；要同一种姿势换位置，需要插件先提供对应版式。

发布身份接口：

- `POST /fish-dandan/api/creative-studio/account`：请求体 `{ handle }`，保存用户自定义的发布昵称；昵称为空时回落到人格自己的名字（当前是 `蛋蛋`），再兜底 `蛋蛋`，不读主人昵称。
- `GET /HEAD /fish-dandan/api/creative-studio/account-avatar`：读取最近一次保存的发布头像；没有头像时 404。
- `POST /fish-dandan/api/creative-studio/account-avatar`：请求体 `{ dataBase64 }`，只接受 PNG，最大 8MB；浏览器端先裁成 512×512 再上传。头像保存在宿主 `data/creative/account/avatar.png`，渲染时作为 `account.avatar` 传给插件。

昵称默认优先级：已保存的自定义昵称 → 人格自己的名字（当前是 `蛋蛋`）→ 固定兜底 `蛋蛋`。**不使用主人的抖音昵称**；这个字段是作品卡上“蛋蛋自己”的发布身份。头像没有上传时，渲染回落到插件角色自带的头像。

运行环境与渲染接口：

- `POST /fish-dandan/api/creative-studio/detect-python`：页面「检测本机 Python」按钮使用；优先扫描 DSH 自带 Python，再扫描系统 Python，返回候选、选中项和下载链接，不下载、不安装、不执行插件代码。
- `POST /fish-dandan/api/creative-studio/prepare-runtime`：页面「安装依赖」按钮使用；宿主内部选择 Python、创建隔离 venv 并安装依赖；只接受用户点击。准备期间客户端轮询 `GET /creative-studio` 的 `runtime.progress` 更新进度条。
- `POST /fish-dandan/api/creative-studio/render-image-post`：后端再次检查安装、能力、运行环境和单任务锁，然后生成参数并渲染。
- `GET /fish-dandan/api/creative-studio/file?job=<job_id>`：只读创作工作室最近一次结果返回的图片；图片必须仍在插件目录内，拒绝越界路径和符号链接。宿主不再按自己的导出目录猜图片位置。

渲染失败码：

- `CREATIVE_STUDIO_NOT_INSTALLED` / `CREATIVE_STUDIO_INVALID` / `CREATIVE_STUDIO_UNSUPPORTED`
- `CREATIVE_STUDIO_BUSY` / `CREATIVE_STUDIO_RUNTIME_NOT_READY`
- `LLM_UNAVAILABLE` / `CREATIVE_COPY_INVALID` / `CREATIVE_BODY_TOO_LONG`
- `CREATIVE_CAPTION_TOO_LONG` / `CREATIVE_VOICE_OFF`（配文超长或命中社媒套话，用户看到“再生成一次”）
- `QA_FAILED` / `RENDER_FAILED` / `RENDER_TIMEOUT`

## 4. 后续阶段

### 阶段 B0：本地安装（已实现）

- 主按钮“从 GitHub 安装”旁的箭头展开菜单，菜单里进入“从本地安装”。
- 填写本机绝对路径，宿主校验目录契约后写入安装记录。
- 只登记目录，不复制、不执行、不改动原项目。
- 同一时间只能有一个本地安装；要换目录必须先卸载。
- 本地卸载只删登记、把页面还原为未安装，不删插件目录、不删同级依赖目录、不删用户 Python。
- 安装完成后还要检测 Python、安装依赖，才能生成图文。

### 阶段 B1：GitHub 安装器（未实现）

1. 只接受 `https://github.com/<owner>/<repo>` 或 `owner/repo`，拒绝任意 URL 和本地路径。
2. 下载仓库文件树到临时目录，校验目标文件都在允许的相对路径内。
3. 校验 `pyproject.toml` 的项目名；不满足就拒绝安装。
4. 安装完成后准备同一个隔离运行环境：venv 放在插件同级的 `dandan-creative-studio-runtime`，不把依赖装进宿主全局 Python。
5. 安装完成后写 `data/state/creative-studio.json`，`source: "github"`、`managed: true`，状态改为 `installed`，但仍不自动生成内容。
6. 卸载走同一个卸载接口：删除 `data/plugins/dandan-creative-studio` 的平台副本、同级的 `dandan-creative-studio-runtime` 依赖目录和记录，不碰用户的 Python、宿主数据或其他项目。

### 阶段 C：心情到参数与渲染（已实现）

1. 宿主读取 `decision.getInternalState()` 和 `persona.current()`；不带聊天记忆。
2. 默认模型输出主题、角色、`hook`、`body`、`highlights`、`caption`；宿主提供可用枚举并做硬校验。
3. 正文太长、JSON 坏掉、高亮不是精确子串时重试一次；仍失败原样报错，不静默换模板。
4. 宿主只把参数写成 `data/creative/inputs/<id>/plan.json` 和 `job.json`，job 用绝对 `plan_path`；这是输入暂存，不是产物目录。
5. 调用 `python -m studio render-job --job <job.json>`，`cwd` 为插件根；参数数组直传，不拼 shell。宿主不传 `--out-root`，也不替插件决定输出目录。
6. 创作工作室默认把产物写到它自己的 `data/exports/<job_id>/`；宿主只读取返回 JSON 里的 `output_dir`、`image` 和 QA，`qa.errors` 必须为空才展示。
7. 页面只展示本地预览；最近一次结果写 `data/state/creative-studio-last.json`。自动发布读取这份状态和同目录 `plan.json`，把图片、标题、正文交给 `publishImagePost`，发布本身仍走真实网页。
8. 存储页只读展示当前作品的大小与只读状态，不提供删除按钮；`data/creative/account/` 和 `data/creative/inputs/` 由宿主自己管，渲染结束后输入目录自动收掉。

## 5. 安全边界

- 插件安装/调用必须是用户显式点击，不在插件启动时自动执行第三方代码或 pip 安装。
- Python 依赖只进隔离 venv：无论 GitHub 版还是本地版，venv 都在插件目录同级的 `<插件目录名>-runtime`；不装进宿主 Node 项目、不装进插件目录内部，也不装进全局 Python。
- 不把 GitHub URL、文件名、job id 直接拼进命令行；spawn 用参数数组。
- 不把插件输出路径、宿主绝对路径写进公开日志。
- 不把登录态、Cookie、人格原文或聊天记忆传给创作插件；只传生成图文需要的字段。
- 插件不可信时，状态的降级是“未安装/不完整/依赖未安装”，不是“看起来能用但点了报错”。
