# 10 · 表情包与多平台发送设计

> 状态：**库与语义检索已写进代码（M1）**，评论/回复图片与私信发图已接入；2026-11-13 已现场验证：私信红心贴纸真实发出；评论「文字 + 蓝胖鱼红心」真实发出。发送成功后评论输入框会清空；此前把“重新填进去的草稿”误当成“发送后保留”，导致同一条评论被测试重复发了三次，现已把发送逻辑收紧为每次调用只发一次。
> 依据：用户要求「表情包不是开关，是功能；一开始空的，能从外部下载、也能自己上传；之后在抖音/B站/QQ 聊天里发」，
> 以及本轮对社区实现（AstrBot 表情包管理器、dsh-pet、nonebot 表情包插件、dsh-qq-bridge）和三个平台能力的调研。

## 一、结论先行

1. **表情包库是跨平台共享的一个功能，不是开关**。初始化时是空的，靠「上传」和「从链接导入」往里攒；素材只落本机 `data/stickers/`，**不进 git、不打包**。
2. **库的元数据必须记来源与许可**。社区教训一致：抓来的图只能自己用、不能随插件分发；分享时给 manifest 和空目录。
3. **发送是适配层的事**。库里只存图；发出去是「图片消息」还是「表情消息」由平台决定：
   - QQ：`image`（图片）与 `mface`（商城表情）/`face`（内置表情）是两回事，`image` 要 `sub_type` 处理；
   - B站：私信图片必须先传到 B站图床，动态发图走 `upload_bfs`；
   - 抖音：**评论/回复发图走输入框右侧图片按钮的隐藏上传入口**；2026-11-13 实测评论 Draft.js 编辑器直接 Ctrl+V 图片时虽然收到 `image/png` 的 paste 事件，但不会插入缩略图，图片按钮上传则正常。缩略图出现只说明上传开始，要再等服务端收完约 1.5 秒；发送成功后输入框会清空，每次调用最多只点一次发送，避免重复评论。私信输入框直接 Ctrl+V 会弹出「发送给 xxx」确认框；私信要求双方互相关注（对方关注你之后，你这边要「回关」才能发消息），陌生人私信受限。
4. **所以顺序是**：先把库和「自己选表情」做好（已完成）→ QQ 发表情（字段最清楚）→ B站动态发图 → 抖音发作品（创作者后台比私信稳）→ 最后才碰抖音私信图。

## 二、已实现（M1）

```
data/stickers/            # 全部被 .gitignore 挡住
  packs/<pack-id>/<sha256>.<ext>
  index.json              # 每张图的元数据
  packs.json              # 包级元数据
```

- 代码：`src/stickers/index.js`（纯 ESM、零依赖、内置 fetch）。
- 能力：`ingest`（魔数嗅探 → 哈希去重 → 写盘 → 记索引）、`upload`（base64）、`importUrl`（http/https 下载）、`list/get/filePath/remove/stats/toRef`。
- 安全：只收 PNG/JPEG/GIF/WebP（**不收 SVG，防脚本注入**）；单张默认 8MB；链接只允许 http/https；哈希去重。
- 接口：`GET /stickers`、`GET /stickers/file?id=`、`POST /stickers/upload`、`POST /stickers/import`、`POST /stickers/delete`、`POST /stickers/meta`。
- 语义：每条可记 `caption`（这张图本身在说什么）、`intents`（适合的场景）、`avoid`（不要用的场景）、`confidence`；`search({q,intent})` 按「图的意思 + 当前对话」打分，`tagOnly` 只按分类兜底（最高 0.38）。网页上点一张图就能补这句话，平时不占版面。
- 概率：表达浓度分 `restrained / natural / playful` 三档；自然档文字 emoji 0.22、评论面板 0.20、自定义表情包 0.50。图与文字 emoji/面板表情互斥，一条消息最多一个表达层；严肃、冲突、求信息、讲长信息不硬配图。
- 网页：平台页「表情包」卡——上传按钮、链接导入、标签、网格缩略图（悬停才出现删除），来源与许可收在折叠区。
- 测试：`test/stickers.test.js` 6 项（魔数、去重、拒文本/超大、base64、URL 导入失败不落库、删除清文件）。

## 四、发送适配设计（M2）

平台适配器新增：

```js
// 适配器能力声明
media: { image: 'file' | 'base64' | 'url', sticker: true, maxBytes: 8 * 1024 * 1024, formats: ['png','jpg','gif','webp'] }

// 发送入口
sendSticker(conv, ref)  // ref = { id, mime, bytes, path, animated, caption }
```

- QQ（OneBot 11）：`image` 段用 `base64://`，大表情加 `sub_type: 1`；内置表情用 `face`；商城表情用 `mface`（要 package/id/key，通常拿不到，先不做）。
- B站：私信图片先用 `upload_bfs` 传图床，再带 `img_src` 发消息；动态发图走 `upload_bfs` + `pics`。
- 抖音：评论/回复走输入框右侧图片按钮背后的 `input[type=file]`，用 `DOM.setFileInputFiles` 塞图；缩略图出现后还要等约 1.5 秒让服务端收完，再点发送。发送成功后输入框会清空；每次调用最多只点一次发送，不能“Enter 没看到反应就再点红按钮”，否则同一条会重复评论。直接 Ctrl+V 图片在 2026-11-13 当前页面版本不会插入，图片按钮上传可用。私信发图走系统剪贴板 + `commands:['paste']` 的 Ctrl+V，页面会弹出「发送给 xxx」确认框，再点「发送（1）」；没有确认框就整条不发，避免“文字发出去了、图没发出去”。

「自己挑表情」的模型工具（M2 一起做）：`sticker_search { mood, q, limit }` → 返回 topN 的「id + 一句话描述」，模型挑中再 `sticker_send { id }`。默认不把整个库塞进提示词（dsh-pet 的 27 张约 650 token 就是教训）。

## 六、许可与风控

- 贴吧、QQ、B站的表情素材版权归各自平台，**抓下来自己用可以，分发不行**；每张图都要记 `source.url/license`。
- 不内置素材、不进 git 是底线；分享只给 manifest 和空目录。
- 平台风控：发图/私信比浏览敏感得多；频率要慢（每步 3-8 秒）、失败即停、识别到验证码就交回人工。
- 自动发布/自动私信有封号风险，默认「仅自己可见」跑通，公开操作要用户点头。

## 九、抖音登录态的真实判定（2026-11-11 深夜踩坑）

- **HTTP 探测不可信**：`probeAlive` 带 Cookie 请求抖音首页返回 200，看起来登录有效；但真正点「关注/私信」时页面弹出「登录后免费畅享高清视频」的扫码/验证码登录框，右上角变成「登录」——**登录态其实已经失效**。
- 正确判定要用**浏览器页面态**：页面出现登录弹窗 / 右上角出现「登录」按钮 / 「私信」按钮置灰，就是没登录；不能只看 HTTP 200。
- 「是否保存登录信息」模态框会周期性弹出并盖住整页，让所有点击失效；它和登录态失效叠加，就是「点了回关没反应」的完整原因。
- 操作顺序必须是：**先确认页面已登录（无登录框、按钮可用）→ 等保存登录信息弹窗消失 → 再点私信**。登录失效时先请用户重新扫码，不要在失效状态下反复点。
- 脚本纪律：一个浏览器实例里耐心走完；不因为一两步没反应就关掉重开（会反复触发弹窗和登录检查）。
## 十、远程整包安装（M1.5，已实现并实测）

用户要求：不要一张张传，要能像别的聊天机器人那样**从远程下载一整套表情包库**。照着 AstrBot 生态做了。

- **格式**：[AstrBot 表情包规范 v0.3](https://github.com/anka-afk/astrbot-meme-pack-index) —— 包根 = `manifest.json`（必填 `schema_version/id/name/version/categories`，可选 `license/author/tags/source`）+ `memes/<分类>/<图片>`；社区索引是 `community-index.json`，`packs[]` 里带 `source{type:'github',repo,ref,subpath}`。
- **入口**：`GET /stickers/remote`（拉社区索引，5 分钟缓存）、`POST /stickers/install {repo,ref,subpath}`（整包安装）。
- **下载链**：GitHub API `git/trees/{ref}?recursive=1` 一次拿文件清单 → 从 `github.com/<repo>/raw/<ref>/<path>` 逐张取（并发 4）。zipball 在本机网络下会超时，已弃用。
- **代理**：本机 Node 的 fetch 不走系统代理（注册表 `127.0.0.1:7890`），所以有代理时改用系统 `curl` 走 `--proxy`；没代理才用 fetch。探测顺序：环境变量 → Windows 注册表。
- **入库**：只收 manifest 里声明过的分类；图片逐张过魔数嗅探与哈希去重；元数据记 `packId/packName/license/sourceUrl/分类 tag`；包信息登记进 `packs.json`。
- **限制**：单包默认最多 200 张（`maxImages`）；文件树被 GitHub 截断（超大仓库）会明确报错；许可只记录不校验，分发前要自己看。
- **前端**：表情包卡里的折叠区「从远程装一整套」——点「加载社区列表」看包里有什么，点「装这个」整包下载，完成后提示新增/重复张数。
- **实测**：装「丛雨表情包」20 张（限 20 张测试）耗时 21 秒，6.4MB，含 4 张动图；重复安装全部命中去重；包信息（名称/版本/许可/作者/标签/来源）都落盘。

测试：`test/stickers-remote.test.js` 5 项（zip 解包、索引 base64、整包安装只收已声明分类、重复去重、无 manifest 拒绝），全量 222 项通过。
## 十一、浏览器常驻与抖音私信实测（2026-11-11 深夜续）

用户要求：**抖音窗口开一次就留着，别频繁开关；一件事做完可以继续做下一件。**

- **固定档案**：浏览器不再每次用临时目录，统一用 `data/browser-profile`；登录态/缓存留在档案里，下次开同一个窗口就能接着用。
- **复用而不是新开**：`cdp.ensureBrowser()` 先探测端口上有没有活着的浏览器，有就直接连，没有才启动；所有需要浏览器的操作都走它。
- **登录成功不关窗**：扫码成功后窗口保留（以前会自动关），后续刷流/私信直接在同一个窗口里做。
- **独立存活**：浏览器进程 `detached`，脚本退出也不带走窗口；下次用 `ensureBrowser` 直接接回。
- **CDP 超时**：`cmd` 默认 20 秒超时，页面死掉不会让调用永远挂住；`attachPage` 支持按 URL 片段找页面，不会连错标签。

实测（同一窗口、一次启动、全程不关）：
1. 页面就绪 → 处理「保存登录信息」弹窗；
2. 点「回关」→ 第 3 次检查到已是关注状态（成功）；
3. 点「私信」→ 输入框出现 → 鼠标点输入框 → `Input.insertText` → Enter → **页面出现「在吗，我来啦。」，文字私信发送成功**。
4. 发图：私信面板里没有常驻的 `input[type=file]`，工具栏的文件夹图标需要点了才出现文件选择；已接好 `Page.setInterceptFileChooserDialog` 拦截 + `DOM.setFileInputFiles` 的方案，图标定位还没测准，下一步继续。

## 十三、下载卡死事件循环的修复（2026-11-12 凌晨）

用户反馈：下载表情包时网页和 DSH 都卡死，进度条不动，其他页面也加载不出来。

**根因**：Node 是单线程，整包下载里有两处同步操作把事件循环堵死：

1. **代理下载用了 `execFileSync('curl', …)`** —— 同步等待子进程，每张图都把主线程卡住几百毫秒到几秒；并发 worker 名义上是 4 个，实际仍是串行阻塞。DSH 的本地 HTTP 服务跑在同一个线程里，所以网页请求、进度轮询全部排队。
2. **入库用 `fs.writeFileSync` / `mkdirSync`** —— 每张图同步写盘，进一步叠加阻塞。

**修复**：

- `curlGet` 改成 `execFile` + `promisify` 异步执行，不再阻塞事件循环；
- `library.ingest` 的文件写入改成 `fs.promises.mkdir/writeFile`；
- 顺带修了两个下载链路上的真问题：`execFileSync` 的 import 被误删导致代理探测静默失败（回退到直连全超时）、部分仓库的 `manifest.json` 带 UTF-8 BOM 解析失败（现在去掉 BOM）。

**实测**：下载 10 张（7 秒）期间，同时每 100ms 请求一个本地 HTTP 服务，63 次采样最大延迟 **15ms**（修复前会是数百毫秒到数秒）。也就是说下载时网页完全可用、进度条会动。
