# 21 · 形象库与角色素材设计（2026-11-13）

> **2026-11-13 方案变更**：13 张原图不再进 Git，改走 GitHub Release `character-dandan-v1`；仓库内只保留 640×360 缩略图、`manifest.json` 和 `assets/character-packs.json`。下载、4 worker 并发、SHA-256 校验与本机安装细节见 [22 号稿](./22-形象资源包下载设计.md)。本稿下面的“内置素材 / 进 Git”表述按此变更理解。

> 目标不是做一个“看图片”的相册，而是给蛋蛋一个稳定的**身份锚点**：
> 以后发抖音图文、做动画、做视频、拆解别人的视频做同款，都从这里选一张三视图当参考底图。
> 当前先把初始形象归档、能看、能传、能设主形象；创作入口放到第二阶段，不先放死按钮。

## 一、先拍板的名字

| 位置 | 名字 | 理由 |
|------|------|------|
| 左侧导航 | **形象** | 和其他两字导航（人格 / 记忆 / 平台）一致，短、好扫 |
| 页面标题 | **形象库** | 明确这里不是单张头像，而是多年龄段、多换装、多版本 |
| 内部 id | `character` | 代码、API、hash 都用这个；不要用 `avatar`，它只代表头像 |
| 不叫 | 头像 / 素材 / 相册 | “头像”太窄；“素材”太泛；“相册”没有身份含义 |

导航顺序建议：

```
当前状态
从零配置
人格
形象          ← 新增
记忆
行为与调度
平台
表情包
安全
```

放在“人格”后面，是因为**人格是它是谁，形象是它长什么样**；两者都属于身份层，放一起比塞到“表情包”旁边更顺。

交互规则：

1. 点缩略图 → 左侧大预览和右侧详情一起切换；选中卡片加 2px 主色描边。
2. 年龄段和造型是**筛选**，不是文件夹；所有图仍在同一个 `assets/character/dandan/`。
3. “主形象”是状态，不是图片属性；同一时间只有一个主形象，写入 `data/state/character.json`。
4. 内置图只读：可以设主形象、下载、复制文件名，不能删除、不能改元数据。
5. 本机上传图可改标题/标签、可删除；删除只删 `data/characters/`，不动内置素材。
6. 空状态：`还没有上传过形象。先把三视图放进来，之后发图文、做动画、做视频都用它当参考。`

## 三、数据模型

### 3.1 两个来源，一个视图

```
assets/character/dandan/manifest.json         内置元数据、进 Git、只读
assets/character/dandan/*-thumb.webp          缩略图、进 Git
assets/character-packs.json                   Release 下载清单、进 Git
data/characters/packs/dandan-initial/         本机安装的原图、被 .gitignore 忽略
data/characters/index.json                    本机上传、被 .gitignore 忽略
data/state/character.json                     当前主形象、本机状态、不进 Git
```

运行时合并成一个列表；`origin` 字段区分 `release` / `upload`。内置缩略图永远可读；原图只有下载安装后才可读。网页不直接读文件系统，只走 API。

### 3.5 为以后留的字段

| 字段 | 现在 | 以后 |
|------|------|------|
| `ageGroup` | `child` / `teen` / `adult` | 按年龄筛选、成长线对比 |
| `outfitId` | 四套内置造型 + `custom` | 按心情/季节/场合选衣服 |
| `variant` | `v1`–`v8` | 同一造型的迭代版本 |
| `tags` | 中文标签 | 搜索、图文选题、自动配图 |
| `viewType` | `turnaround-sheet` | `single-illustration` / `expression-sheet` |
| `threeView` | `true` | 判断能否直接做动画参考 |
| `isOrigin` | 初始形象 | 身份锚点，生成时优先锁脸 |
| `isPrimary` | 当前主形象 | 首页卡片、默认创作形象 |
| `license` / `rightsConfirmed` | 内置 CC / 上传确认 | 商用边界、发布前检查 |

### 3.6 体积与缩略图

13 张 2848 × 1600 PNG 原图合计约 **74MB**，不能直接塞进列表。

- 同目录生成 `*-thumb.webp`，640 × 360，quality 82，当前 13 张合计约 **0.51MB**；
- `manifest.json` 每张图带 `thumbFile`；列表/卡片只请求 `/characters/thumb?id=...`；
- 详情页和下载才请求 `/characters/file?id=...`；
- 懒加载：网格用 `loading="lazy"`，首屏只预载主形象和第一屏缩略图；
- 用户上传图同样在保存时生成一张缩略图，存 `data/characters/`，不进 Git。

## 四、API 设计

统一挂在 `/fish-dandan/api` 下，沿用现有 loopback + Host/Origin 校验。

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/characters` | 返回角色信息、分组、造型、合并后的图片列表、统计、主形象 |
| GET | `/characters/thumb?id=...` | 返回 640×360 WebP 缩略图；列表和卡片只加载这个 |
| GET | `/characters/file?id=...` | 返回原图；详情页和下载才加载 |
| POST | `/characters/upload` | 上传本机图片；base64 JSON，≤ 12MB；写 `data/characters/` |
| POST | `/characters/meta` | 改本机上传图的标题、年龄、造型、标签 |
| POST | `/characters/delete` | 只删本机上传图；内置图返回 403 |
| POST | `/characters/primary` | 写 `data/state/character.json` |
| GET | `/characters/reference-pack?id=...` | **第二阶段**：给创作流程返回图片 URL、尺寸、年龄段、标签、许可 |

`/characters` 返回示例：

```json
{
  "ok": true,
  "character": {
    "id": "dandan",
    "displayName": "蛋蛋",
    "aliases": ["大肥鱼", "DeepSeek 鲸鱼娘"],
    "defaultImageId": "child-initial-maid",
    "primaryImageId": "teen-initial-maid-v1"
  },
  "groups": [...],
  "outfits": [...],
  "items": [...],
  "stats": {
    "total": 13,
    "release": 13,
    "uploads": 0,
    "byAge": { "child": 3, "teen": 10, "adult": 0 }
  }
}
```

### 安全边界

- 只接受本机回环；沿用现有 `isLoopbackAddress` / `isLoopbackOrigin`。
- `file` 只接受 `id`，不接受路径；服务端从 manifest / 索引反查文件，拒绝 `..`、绝对路径、盘符。
- 上传只收 PNG / JPEG / WebP；不收 SVG（XSS 风险）、GIF（三视图不需要动图）。
- 上传上限 12MB；base64 解码后校验文件签名和实际字节数，不信任客户端 MIME。
- 删除只允许 `origin: "upload"`；内置图不可删、不可改元数据。
- 用户上传文件放 `data/characters/`，已被 `data/*` 忽略，不会进 Git。
- 页面显示许可和“非商业”提示；上传必须勾选“有权使用”。

## 五、网页实现落点

现有设置页在 `src/gui/web/index.html`，导航是 `data-tab` 按钮，页面由 `renderX()` 重建。新增时按现有模式走，不引入新框架。

1. **导航**：在 `data-tab="persona"` 后插入 `data-tab="character"`，图标用“人物 + 画框/三视图”的线性 SVG。
2. **状态**：`TABS` 增加 `"character"`；`S` 增加 `characters: { data, selectedId, filter, uploadOpen, loading }`。
3. **页面函数**：
   - `renderCharacters()`：首屏骨架、筛选条、主形象卡、预览区、详情区、网格、上传入口。
   - `loadCharacters()`：`GET /characters`，合并后写入 `S.characters.data`；默认选主形象，没有就选 `defaultImageId`。
   - `paintCharacters()`：只重画筛选后的网格、预览、详情，不重建整页。
   - `bindCharacterPage()`：筛选、选中、设主形象、上传、删除、复制文件名。
4. **上传**：复用表情包页的 `readFileBase64()`；提交 `POST /characters/upload`；成功后刷新列表并选中新图。
5. **CSS**：新增 `.char-*` 命名空间，复用现有 `card`、`btn`、`chip`、`input`、`stack`、`skeleton`；不复制一套新设计系统。
6. **后端**：新增 `src/character/library.js`，由 `src/index.js` 初始化并传给 `registerGui`；`src/gui/api.js` 增加 `'/characters'` 等 handler。
7. **测试**：
   - manifest 的 `id` 唯一、文件存在、宽高匹配；
   - 合并列表里 release + upload 顺序、统计正确；
   - `file` 拒绝路径穿越和未知 id；
   - 上传拒绝 SVG、超大文件、无授权确认；
   - 删除内置图返回 403；
   - 主形象持久化后重新加载仍生效。

## 六、第二阶段：从“看形象”到“用形象创作”

这一层先设计接口，不先做按钮，避免又出现死入口。

### 6.1 创作素材包

`GET /characters/reference-pack?id=teen-initial-maid-v1&target=douyin-gallery`

返回：

```json
{
  "ok": true,
  "characterId": "dandan",
  "imageId": "teen-initial-maid-v1",
  "ageGroup": "teen",
  "outfitId": "initial-maid",
  "imageUrl": "/fish-dandan/api/characters/file?id=teen-initial-maid-v1",
  "width": 2848,
  "height": 1600,
  "threeView": true,
  "tags": ["少女", "女仆", "深蓝"],
  "license": "CC-BY-NC-SA-4.0",
  "commercialUse": false
}
```

创作流程拿这个包，不再自己拼文件路径。

### 6.2 四种用途

| 用途 | 用哪张 | 需要的额外输入 |
|------|--------|----------------|
| 抖音图文 | 三视图整张，或裁正面/细节 | 文案、封面比例、发布账号 |
| 动画 | 正面 + 侧面 + 背面 | 动作、镜头、帧率、时长 |
| 视频 | 三视图 + 单张立绘 | 分镜、运镜、场景、配音 |
| 做同款 | 先拆解目标视频，再选形象 | 目标视频、镜头结构、替换规则 |

### 6.3 蛋蛋自己选衣服

以后给 `outfits` 增加：

```json
{
  "id": "initial-maid",
  "label": "初始深蓝女仆装",
  "ageGroups": ["child", "teen"],
  "vibe": ["经典", "乖巧", "日常"],
  "formality": "daily",
  "season": ["春", "秋", "冬"]
}
```

决策层按“当前心情 + 平台 + 季节 + 是否正式”选 `outfitId`，再取该造型下最新的 `primary` 或 `v1`。第一版先由用户点选，不自动换。

### 6.4 发布边界

- 生成内容先落本机，发布走人工确认；不因为“形象库有图”就自动发抖音。
- 商用/带货前检查 `rights.commercialUse`；内置素材是非商业，不能直接用于商业投放。
- 用户上传图必须带 `rightsConfirmed`，没有确认的图不进入创作候选。

## 七、验收标准

1. 左侧出现 **形象**，页面标题 **形象库**，刷新后 hash 能回到 `#character`。
2. 首屏能看到 13 张内置图，幼年 3 / 少女 10 / 成年 0，主形象默认是 `06-teen-initial-maid-v1`。
3. 筛选“幼年 / 少女 / 成年”和“女仆 / 水手 / 星庭 / 极光”正确；筛选后计数同步。
4. 点任意缩略图，预览和详情切换；设为主形象后刷新仍保留。
5. 上传一张 PNG，填写年龄/造型/标签并勾选授权，能在列表出现、能设主形象；`git status` 不出现新文件。
6. 删除上传图后列表恢复；删除内置图被拒绝。
7. `GET /characters/file?id=../...` 被拒绝；未知 id 返回 404。
8. `npm test` 通过；新增测试覆盖 manifest、合并、上传校验、路径穿越、主形象持久化。

## 八、这一轮不做的

- 不做“用这张创作”按钮：创作流水线还没接，先不放死入口。
- 不做多角色管理界面：数据结构支持 `characterId`，但页面先只展示蛋蛋。
- 不做自动换装/自动发布：第二阶段再接决策层和人工确认。
- 不把用户上传图放进 `assets/` 或 Git。
- 不替换现有 `assets/icon.png` / `avatar.png`；形象库是新增素材层，不动旧图标。
