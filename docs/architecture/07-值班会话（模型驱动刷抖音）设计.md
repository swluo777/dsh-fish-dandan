# 07 · 值班会话（模型驱动刷抖音）设计

> 状态：**M1 + M2 已落地（2026-11-11 晚）**；同日晚修复「精选页刷不动」和「点停止后浏览器不关」两个真 bug（见第十一节）。
> 深夜按用户澄清修正语义：**主开关是「允许它用抖音」的授权，不是「开始看视频」的剧本**（见第十二节）。
> 值班模式默认关；开关在抖音卡「详细设置 → 值班模式」。
> 已实现：`duty.js`（spawn/隔离 profile/单飞/超时/事件导入/停止）、`duty-server.mjs`（MCP：status/look/react/say/memory/finish）、
> `prompts/douyin-duty.md`（章程）、聊天工具 `douyin_run` / `douyin_state`、GUI 开关与统一入口 `startRound`。
> 待办（M3 增强）：谷时偏好、成本统计面板、rpid 级楼中楼定位、读弹幕。
> 表达层（什么时候发文字、面板表情或自定义表情包，失败怎么回退）以 [06 表达层决策链任务单](../ai-handoff/06-表达层决策链任务单.md) 为准。
> 背景：过去有一版纯宿主脚本——打开页面、往下翻、抓文案、按正则打分，全程没有模型参与。2026-11-13 起生产只保留模型值班，脚本实现已标为 LEGACY。
> 结果它不知道自己在刷什么、停在「精选」也不会切、说的话是词库拼的、刷完什么都没记住。
> 用户 2026-11-11 确认方向：**把刷抖音交给模型，宿主只准备工具和护栏**。

## 一、结论先行

1. **触发不需要用户说话**。三条路都汇到同一个入口 `duty.start(why)`：
   - 设置页按钮「让它刷一轮（会思考）」；
   - 决策循环到点（心情/时段到了，跟现在的自动刷同一个调度）；
   - 聊天里说「刷抖音」→ 模型调用我们注册的 DSH 工具 `douyin_run`（`dsh-douyin-scroll` 就是这么做的：`tool({ name: 'douyin_run', … })`）。
2. **值班不在聊天窗口里刷**。每轮起一个独立的 headless DSH 会话（`dsh --profile douyin-duty --patch overlay "<duty 提示词>"`），模型在里面用一组窄工具一步步刷；刷完写日记、写日报、退出。聊天里之所以能"知道"，靠的是它**直接写我们的记忆库**——这是我们对两个参考项目的差异化（它们只写日报和判重表，不接主记忆）。
3. **宿主保留硬护栏**：时间预算、单轮条数、发言脱敏、可疑内容拦截、单飞锁、超时强杀。模型再自由，也越不过这些线；这是它"自由但聪明"的保证。

## 二、总体架构

```
宿主（插件本体，常驻）
 ├─ 登录态 / 设置 / 记忆 / journal / GUI / 决策循环
 ├─ 触发：按钮 / 到点 / 聊天工具 douyin_run
 │    └─ duty.start(why)
 │         └─ spawn `dsh --profile douyin-duty --patch overlay "<值班提示词>"`
 │              overlay 做三件事（抄 dsh-douyin-scroll 的做法）：
 │                ① 打开 headless 默认禁用的 credentials / authorization / deepseek-account
 │                ② 跟随当前选中的模型（provider/model 内联进 overlay）
 │                ③ 挂 @deepseek-ai/dsh-mcp-client → 起我们的 mcp-server.mjs
 │              mcp-server 进程（stdio 工具服务端）：
 │                ├─ 持有浏览器：共享浏览器里的可见活动标签页（固定围观 + bringToFront）
 │                └─ 模型通过工具一步步刷：look → 想 → react / say → next → …
 │                └─ 收尾：douyin_finish 写日记 + 日报 + journal
 └─ duty 进程退出 → 宿主结算时间、执行延迟动作、审计
```

与参考项目的差别：

| | dsh-bili-scroll / dsh-douyin-scroll | 我们 |
|---|---|---|
| 值班会话 + 窄工具 | ✅ | ✅（同一套机制） |
| 日报 | ✅ out/*.md | ✅（轻量，可选） |
| 写进主记忆 | ❌（只写报告/判重表） | ✅ **工具直写三层记忆**，聊天可回忆 |
| 围观（固定） | ❌（无头 + 截帧） | ✅ 可见窗口，真的看着它刷 |
| 互动触发 | 模型只出草稿，宿主轮末执行 | 模型当场决定，宿主工具当场执行（仍受护栏） |

## 三、工具面 = 安全边界

mcp-server 只注册白名单里的工具，**名字都不给模型看见**（抄 douyin 的原则）：

| 工具 | 作用 | 护栏（宿主强制，不靠提示词自觉） |
|---|---|---|
| `douyin_status` | 还剩多少时间、动过什么、被允许做什么 | — |
| `douyin_open` | 去任意页面：recommend / following / me / search / video / url | 只接受抖音域名链接；时间预算到了就提醒收尾 |
| `douyin_look` | 读当前这条并返回快照（id/文案/作者/互动数/前 N 条评论）；读到一条新的会停在这条，当前这条看过才翻下一条 | 累计到「单轮条数」或「时间预算」→ 返回"额度用完，请收尾"；页面被自己翻走时返回失败，不把旧评论挂到新视频 |
| `douyin_react` | 点赞 / 收藏（关注已整体关闭） | 可疑内容拦截；已互动去重；动作前核对当前 video.id |
| `douyin_say` | 评论 / 回复（通用转发已关闭；仅保留分享当前视频给主人；视频页私信作者已关闭） | `checkOutbound` 脱敏 + 字数上限；评论/回复必须带当前 video.id，服务端核对，防串台 |
| `douyin_share_to_owner` | 把当前视频作为分享卡片发给主人；可选附一句 `text` | 目标固定主人，没有 `to`；必须核对当前 `videoId`；每次值班最多一条；带文字必须先读 `douyin_owner_memory`，并同时打开私信；卡片成功、文字失败返回 `partial=true` |
| `douyin_dm_send` | 主动私信（低频） | 可发给主人或想找的人；工具硬限频：两次至少隔 10 分钟、每小时最多 2 条 |
| `douyin_send_sticker` | 发表情包（低频） | 和主动私信共用频控；可发给主人或收件箱会话 |
| `douyin_self` | 读自己的账号：昵称 / 抖音号 / 签名 / 关注 / 粉丝 / 获赞 | 只读自己的主页 |
| `douyin_update_self` | 改自己的昵称 / 简介：点昵称旁铅笔 → 弹「编辑资料」→ 填 → 保存 → 回读校验 | 保存后回读不一致会如实说明；头像上传留到「本鱼的形象」那一步 |
| `douyin_memory` | 写一条第一人称记忆（"我今天刷到了…"） | 只追加，带 `douyin` 标签 |
| `douyin_finish` | 收尾：写日记 + 日报 + journal，然后退出 | — |

- **没有固定配额**：动不动由模型按当时的心情和内容判断（呼应"按心情来"）；硬护栏只剩时间、条数、发言卫生。
- **频率分层**：由值班章程管（点赞高频、评论偶尔、收藏更少；关注 / 通用转发暂不开放；可分享给主人），宿主不管每类配额。

## 四、值班提示词（`prompts/douyin-duty.md`）

结构（参考两边章程，按我们的人格写）：
1. 开场：读 `douyin_status`，确认登录与预算；
2. 循环：`douyin_look` → 想一想（这是什么、我现在的情绪会怎么做）→ `douyin_react`/`douyin_say`（可不动作）→ 继续或收尾；
3. 说话规矩（抄 bili 的五道闸门，换成我们的人设）：一句人话 + 只有看了这条才说得出的细节；一个梗最多用一次；不写"本期视频…"八股；不编画面；评论区骂人不接；
4. 红线：不透露账号/路径/密钥；色情、暴力、谣言、政治敏感直接跳过；不确定就不说；
5. 收尾：`douyin_memory` 写日记（第一人称）、`douyin_finish`。

人设来源：优先用插件自己的 persona（名字/自称/口癖/styleNotes 内联进提示词），不再让用户单独填一份——这是我们对 douyin-scroll "人设要另填"的改进。

## 五、围观模式（固定）

- `douyin_look` 不是"读完就翻页"：读当前这条并停在它上面；只有当前这条已经看过，或模型再调一次，才翻下一条。宿主 mcp-server 用同一套 CDP 逻辑（`readSnapshot` / `nextVideo` / `playbackState`）。
- 活动标签页始终可见 + `bringToFront`，**用户看到的就是模型正在看的那一页**；它每一步思考的产物会体现在下一个动作上。2026-11-13 用户拍板：静默模式下线，不再提供无头或屏幕外活动。
- 「停止」= 宿主写 `stop` 标志（让模型有机会收尾）→ **2 秒后 `taskkill /T /F` 杀掉整棵值班进程树** → 再按
  `data/duty/browser.pid` 兜底关掉 Edge（duty-server 启动浏览器后写下这个 pid）→ 500ms 后轮询到 `running=false` 界面立刻恢复。
  以前是「先等 25 秒再 `child.kill()`」：只杀 CLI 父进程，MCP 子进程和浏览器会变成孤儿，用户看到的就是「点了停止，什么都没发生」。
- 宿主侧 `duty.snapshot()` 多了 `stopping` 字段，网页在停止过程中显示「正在停止…」并禁用按钮，不会卡在旧状态。

## 六、降级与失败（失败要出声）

| 情况 | 处理 |
|---|---|
| 找不到 dsh CLI | 明确报错（状态行 + toast），**这一轮不刷**；2026-11-11 用户拍板：**绝不退回脚本翻页** |
| `dsh --profile douyin-duty` 铺不上 / spawn 失败 | 同上，日志写清原因（学 bili：不许静默降级） |
| duty 超时（如 15 分钟） | kill + 写"这轮没跑完"，释放单飞锁 |
| 并发 | 单飞锁：同一时刻最多一个 duty（bili 用 lock 文件 + pid 超时，照做） |
| 桌面版 spawn 卡住（bili 已知问题） | detached + 日志直写文件 + GUI 手动按钮为第一入口；调度自动跑放后 |

CLI 解析：桌面版运行时自带 `resources/runtime/cli/bin/dsh.cmd`（本机已确认存在），加 `ELECTRON_RUN_AS_NODE=1` 环境变量（douyin-scroll 踩过的坑）。

## 七、成本

- 现在只有模型值班：每轮 20–60 次工具调用，模型用 `deepseek-account` 的 flash 档；按账号计费，一轮大约几毛钱以内（以实测为准）。
- 不存在“0 token 的脚本模式”：旧 `browse.js` / `decide.js` / `will.js` / `voice.js` 已删除，生产只有模型值班。
- 设置里没有独立的「值班模式」开关：总开关「允许它用抖音」打开，就允许模型值班；关掉就什么都不做。

## 八、与现有代码的关系

- **生产只有模型值班**：`adapter.startRound()` 只调 `duty.start()`；`adapter.stopRound()` 只调 `duty.stop()`，找不到 dsh CLI 时直接报错，不退回脚本。
- 旧脚本 `browse.js` / `decide.js` / `will.js` / `voice.js` 已删除；适配器、GUI、聊天、自唤醒都不再引用它们，测试也不再跑旧脚本。
- 新增文件：`prompts/douyin-duty.md`、`src/platform/douyin/duty.js`（spawn/锁/超时/退出/停止）、`src/platform/douyin/duty-server.mjs`（MCP 工具白名单，stdio）。
- GUI：抖音卡「现在去刷一轮」按钮 + 状态说明；`/platforms/douyin/browse`（GET 状态 / POST 开始）和 `/platforms/douyin/browse/stop` 现在都只操作值班，不再有脚本 fallback。
- DSH 聊天工具：`douyin_run` / `douyin_state`（用户在聊天里说“刷抖音”时模型调起值班）。

## 十、风险

- 桌面版 spawn 兼容性（bili 已知卡住问题）→ detached + 超时 + 手动按钮优先；
- 抖音改版 → 工具层集中在 `actions.js`/`douyin.mjs`，改一个文件；
- token 成本失控 → 时间/条数硬上限 + 值班开关默认关；

## 十一、2026-11-11 晚修复记录（真 bug，已实测）

用户反馈两件事：「点停止，提示说会关浏览器，其实什么都没发生，按钮还卡住」「一直停在那一直在刷精选，不会换到推荐页」。逐条查过后：

1. **停在精选**。旧 `openRecommend()` 只在 `header` 里找顶部 tab，新版网页的推荐入口在**左侧导航第二个**（`a[href*="recommend=1"]`），找不到就静默留在精选；精选是卡片墙，没有 `video` 元素，`readSnapshot()` 自然一条都读不到。
   现在：轮询等导航出现（最多 20 秒）→ 点左侧「推荐」→ 等 `feed-active-video` 挂上来（最多 12 秒），点两次还不行才报失败。
2. **推荐页 URL 没有视频 id**。推荐页全屏播放器地址是 `/?recommend=1`，`location.pathname` 里没有 `/video/<id>`，旧逻辑把每次快照都当空。现在从 `[data-e2e="feed-active-video"]` 的 `data-e2e-vid`（或 class 里的 `video_<id>`）取 id。
3. **读到了上一条的内容**。推荐页 DOM 里同时挂着多条 feed，全局 `querySelector` 会命中已经滑走的那条。现在文案/作者/互动数都锁在「活动 feed」的 `feed-item` 里读；`playbackState` 与 `currentVideoId` 同样锁活动视频（围观时长不会再按错误的 `video` 算）。
4. **翻页**。`nextVideo` 改为优先点官方下箭头 `[data-e2e="video-switch-next-arrow"]`，用 id 是否变化判断是否成功（URL 不变也能判断），失败才退方向键与滚动。
5. **停止没反应**。旧实现写 `stop` 标志后干等 25 秒再 `child.kill()`，而 kill 只杀 CLI 父进程，MCP 服务端与 Edge 成了孤儿，界面又因为 `running` 仍是 true 一直显示「值班中」。现在：写标志 → 2 秒后 `taskkill /T /F` 整棵树 → 按 `browser.pid` 兜底关 Edge → 5 秒兜底结算；`snapshot()` 增加 `stopping`，网页显示「正在停止…」并轮询到窗口真的关掉。
6. **互动选择器补推荐页**：点赞 `video-player-digg`、收藏 `video-player-collect`、关注 `feed-follow-icon`（选择器保留，当前不接入口）、评论 `feed-comment-icon`；私信用视频 id 拼 `/video/<id>` 详情页地址（以前打开的是推荐首页）；通用转发已关闭；仅保留分享当前视频给主人。

实测（本机 Edge + 本地登录态）：连续读 3 条不同视频，id/作者/文案/点赞数正确，播放进度取到真实的 10.4s / 17.1s 时长；假 CLI 下 `duty.stop()` 2.2 秒内回到 `running=false`。以上都是真实浏览器验证，不是断言。

## 十二、开关语义修正：授权，不是剧本（2026-11-11 深夜）

用户明确纠正：「自动刷抖音这个主按钮，不是一定要让你去刷视频，而是允许你在抖音上做任何操作，而不是按照一个固定的流程逼着你去看视频。这个东西不要理解歪了。」

按这个改：

1. **界面语义**：开关标题定为「允许它用抖音」，说明是「关 = 它不会去刷，也不能手动开始；开 = 只是允许，不会自己动」；按钮定为「现在去刷一轮」，和「让它自己挑时候去」区分手动/自动；模式标签改为「活动的时候」。
2. **提示词**：`prompts/douyin-duty.md` 从「值守章程（先 status → 一条条 look → 动手 → finish）」重写为「自由活动指南」——能做哪些事、没有固定顺序、条数不是指标；`duty.buildPrompt()` 同步改（不再写"照章程做完整一轮"）。
3. **工具面补足自由度**：
   - `douyin_open`：推荐 / 关注 / 我的主页 / 搜索 / 指定视频 / 任意抖音链接；
   - `douyin_self`：读自己的昵称、抖音号、签名、关注/粉丝/获赞；
   - `douyin_update_self`：改昵称/简介（网页版入口是昵称旁的**铅笔图标**，不是文字按钮；简介是 Draft.js 富文本框；头像上传留到形象那一步）。
4. **顺带修的真 bug**：详细设置里的时长/条数以前绑的是 `browse.sessionMinutes` / `browse.maxVideos`，而值班实际读 `duty.maxMinutes` / `duty.maxVideos`——改了根本不生效；现已改为绑定 duty 预算。
5. **读自己主页**：优先点左侧「我的」，SPA 路由慢时退回直接打开 `/user/self`；昵称/抖音号/签名从资料卡文本解析，关注/粉丝/获赞单独读 `user-info-follow/fans/like`（数字不在资料卡 innerText 里）。

实测（真实浏览器）：读到自己账号「参数世界 / ParamVerse / 纯AI，零真人 / 关注 12 / 粉丝 1 / 获赞 0」；搜索、推荐、回首页都通；「编辑资料」弹窗能打开、昵称与简介能填、保存按钮会从灰变亮（这一步只验证到按钮可用，没有真正保存，等用户定好名字再改）。

**下一步（用户规划，按顺序做）**：① 它自己的形象与头像（先看账号，再自己设置）→ ② 自动做图能力 → ③ 发表情包 → ④ 给主人发消息。

## 十三、单项能力闸门与登录自愈（2026-11-11 深夜补）

用户要求：点赞、关注、评论、回评论、收藏、转发、私信、读评论这些功能，**必须开关打开才能做，关掉就不允许**。以前只有提示词在"劝"，工具层没拦。

1. **能力位一路传到底**：`settings.actions.*` + `browse.readComments` → `duty.settings()` 打包 → `FISH_CAPS` 环境变量 → `duty-server` 的 `capOn()`。
   关掉对应开关时，`douyin_react` / `douyin_say` 直接返回 `{ ok:false, disabled:true, reason:'「点赞」没在设置里打开，这次不做' }`，`douyin_look` 也不再打开评论区读评论。`douyin_status.can` 会按实际开关列出能做什么。
2. **登录状态不再误报「已过期」**：
   - 值班未运行时，快照只返回值班事实 + 流水账统计，不再混入旧 `browse` 的「登录已过期」或今日用量口径。
   - 判成过期后 60 秒自动重验一次（原来要等 12 小时），网络抖动或风控误判能自己恢复。
   - `network-error` 不判过期；扫码保存的会话比上次探测新，就直接视为有效。
   - 实测：本地 56 条 Cookie 轻量请求返回 `alive:true / http 200`，登录态是好的。
3. **记忆页分页**：`/memory` 返回 `total` / `pageCount` / `approximate`（搜索最多取 100 条，标「约」）；页面显示「第 X / Y 页 · N 条」，可直接输入页码跳转。
## 十四、权限模型：只做权限划分，不搞默认定时任务（2026-11-12）

用户拍板：「抖音功能我想给它调整成打开的状态，不限你时长想用就用。关掉的时候就不允许你使用。里面很多的限时啊，定时任务这种我觉得都没有必要。就是我的后台只做权限的划分。不搞定时任务，给权限了，你想干嘛就就可以。没给权限你都不能干。」

按这个彻底改：

- **保留的**：总开关（允许/不允许）、围观（固定可见，静默已下线）、单项能力位（点赞/收藏/评论/回复/私信/分享给主人）、读评论开关与条数、兴趣偏好；关注 / 通用转发 / 发作品暂不开放；分享给主人是独立开关，默认关。
- **删掉的**：值班时长（`duty.maxMinutes`）、单轮条数（`duty.maxVideos`）、单次时长（`browse.sessionMinutes`）、停留区间（`dwellMinSec/Max`）、每日额度/最小间隔/活跃时段（`pace`）、到点自动刷的定时器（`tick`/`ensureTimer`/`autoRunner`）。
- **默认不装任何定时器**：开关打开后不会再「到点自己跑」。想用的时候由用户点「自己待一会儿」，或在聊天里让模型去；模型想待多久、看多少条都随它，直到它自己收尾或被叫停。
- **自唤醒是单独的权限位，不是默认行为**：`douyin.autoWake.enabled` 默认 `false`；只有用户明确打开「让它自己挑时候去」，才会每 20 分钟看一次心情（精力、无聊、静默时段、距上次值班都满足才去），觉得不想去就什么都不做。关掉就立刻摘掉定时器。它不是「到点必刷」，也不绕过总开关、能力位和出站闸门。
- **旧脚本已删除**：`browse.js` / `decide.js` / `will.js` / `voice.js` 不再留在仓库，也不再有 6 小时 / 300 条的脚本兜底上限；值班本身不限时，只有进程卡死 6 小时才兜底结束。
- **状态只看事实**：界面显示「今天用过多久」是统计，不是额度；没有「约 N 分钟后可再刷」这类提示。
- 值班提示词同步改：去掉「时间预算」，改成「没有时间预算，也没有条数指标，想待多久都随你；想走了就收尾」。
- 设置页删掉时长/条数/停留/每天额度/活跃时段五组输入，只留权限与偏好，并在自唤醒折叠区加一个默认关闭的开关，说明「默认不自动跑；打开才每 20 分钟按心情判断一次」。

测试同步更新（平台设置只验权限位、值班提示词无预算、网页无预算配置），数量以 `node --test` 实际输出为准。

## 十五、画面理解与主人喜欢列表（2026-11-13）

### 新增能力位

- `douyin.browse.vision`（默认 `false`）：`douyin_look` 是否截当前视频帧；
- `douyin.owner.profileUrl`（默认带公开示例主页）：主人完整主页链接；
- `douyin.owner.readLikes`（默认 `false`）：是否允许 `douyin_owner_likes` 只读喜欢列表；
- 三项都打包进 `FISH_CAPS` / `FISH_OWNER_PROFILE`，工具层按开关拒绝，不靠提示词自觉。

### 工具变化

| 工具 | 变化 | 护栏 |
|---|---|---|
| `douyin_look` | 画面开关打开时，额外返回当前视频 1-2 帧 MCP ImageContent | 截完再核对 `videoId`；页面翻走就作废；换页清空 `lastSnap` |
| `douyin_owner_likes` | 新增，只读主人主页「喜欢」页签 | 只认完整主页链接；锁着返回 `locked`；不借机关注/通用转发/发作品；10 分钟内缓存 |

### 记忆

- 主对话工具：`fish_memory_search` 只读查长期记忆（主人最近/平台最近/相关经历）；人格段要求遇到“你刚才/之前做了什么、主人最近、记不记得”先查，避免某些会话没注入记忆段时凭当前对话答“没去过”；
- 私信：`dm-auto` 只在主人或 `listen.memoryAllow` 名单内时召回 1-2 条非 anchor 记忆；名单外的陌生人只读当前线程；
- 视频画面：值班收尾按 `douyin_look` 看到的内容写真值事件（`videoId`/文案/作者），模型再用 `douyin_memory` 补画面细节；
- 主人喜欢：`owner-likes` 事件由宿主 `importEvents` 增量导入（值班中每 2 秒一次，半行留到下一轮），写 `person:'主人'`、`tags:['主人','喜欢']`；锁着写低重要度状态；开着把新增标题写成「主人最近：…」摘要，模型再用 `douyin_memory` 补截图里看到的细节。主聊天在下一次上下文求值时就能看到，不用等收尾。
