# 17 · 开源前审计与待办（2026-11-12 凌晨）

> 三路只读审计：核心代码、GUI 与首装路径、文档与 git 卫生。
> 这份记录**哪些已经修了、哪些故意留着**，避免下次又从头查一遍。

## 一、这一轮修掉的

### 首装能用（P0）

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 配置写错类型直接崩 | YAML 少缩进变成字符串，`merged.memory = "x"` 之后赋值抛 TypeError，整个插件起不来 | `resolveConfig` 深拷贝 + 逐段 `isPlainObject` 兜底 + 整段 try/catch；`merge` 遇到「默认是对象、用户不是对象」保留默认并记 warning |
| `DEFAULT_CONFIG` 被污染 | 一次 `resolveConfig` 会改掉默认值，下次读到的静默时段已经变了 | 用 `structuredClone(DEFAULT_CONFIG)` 起步 |
| 端口拼接 | `loginPort` 配成字符串时 `+ 1` 变成 `"92241"` | 端口全部 `num()` 校验，并新增 `browsePort / listenPort / dutyPort` |
| 登录窗口与刷流抢档案 | 登录成功后窗口留着，再开刷流会用同一份 Chromium 档案直接退出 | 后来统一为共享浏览器 hub：一个进程、一份档案、多标签页（见 18） |
| 首装看不出「还没配置」 | 卡片、首页、对话都不提未配置，新用户被默认称呼劝退 | `/overview` 带 `wizard` 状态；卡片显示「还没配置 / 花一分钟认识它」；网页首次进入直接落在「从零配置」 |
| 默认称呼像客服 | 新装就被叫「主人」 | 默认 `ownerAddress` 改成「你」；人格段里的「主人」改为中性表述 |
| 第一次开口像自我介绍 | 首轮没有任何「这是第一次」的上下文 | 新增 `src/persona/first-meet.js`：一次性引导，只在该轮注入，用户真的说过话之后才作废；升级上来的老用户不会触发 |
| 向导最后一步才校验 | 前面随便点，最后报一句看不懂的错 | 解析 AI 结果时有问题就停在第 1 步并列出问题字段 |
| 模板原文被当成人格 | 把模板贴进「AI 结果」框也「解析成功」，名字变成「给它起个名字」 | 解析器加占位符黑名单，命中就跳过并给 warning |
| 首屏台词是调试语 | 首页 hero 显示「初始状态」 | 初始化文案改成「刚被装进来，还谁都不认识，先歇着」 |
| 日志首行丢失 | `data/` 不存在时第一条日志写不进去，且反复刷 stderr | 写前建目录；同一个错误只喊一次；`FISH_SOUL_NO_LOG=1` 可静音 |

### 安全与正确性（P0/P1）

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 私信可能发给陌生人 | `openThread` 找不到目标会话时兜底点第一条 | 删掉兜底：精确同名 → 唯一包含匹配 → 否则报错；返回值带页面真实命中的名字 |
| 回复可能回到别人楼下 | `tSay` 的 reply 兜底 `comments[0]` | 删掉兜底，定位不上就明确报错 |
| 任意本地文件能当表情发出去 | `douyin_send_sticker` 的路径没有任何限制 | 新增 `resolveStickerFile()`：只收 `data/stickers`、`data/images` 下的 png/jpg/gif/webp，拒绝绝对路径与 `..` |
| 任意本地图片能贴进豆包 | `doubao_paint` 的 `refPath` 直传 PowerShell | 新增 `resolveRefImage()`，同样白名单 |
| 「每轮判心情」实际从未生效 | `session/event` 的 `data` 结构取错，永远拿到空串 | 按本机会话日志核实：`user/message` 的 `data` 就是消息，`assistant/message` 才是 `data.message`；测试夹具同步改成真实结构 |
| 记忆检索永远没有 query | `agent/pre-step` 的 payload 里没有 `lastUserMessage` | 改成从 `session/event` 的 `user/message` 取原话，并给记忆层加 `noteUserText()` 兜底 |
| 监听器未导入 | `listener.js` 调用 `closeInbox` 但没 import，报错被吞 | 补 import |
| MCP 协议被日志污染 | 值班服务端 `console` 打到 stdout，会破坏 JSON-RPC 行协议 | 浏览器日志改写到 `duty-server.log` |
| 工具失败模型不知道 | `isError` 两个分支都返回 `undefined` | 改成 `Boolean(result.ok === false)` |
| 主动私信带出隔离记忆 | `memory.list()` 默认包含隔离内容 | 主动搭话只取非隔离记忆，并跟随 `config.platforms.settingsPath` |
| 非 Windows 注册了 Windows 专属工具 | 豆包做图全靠 PowerShell | 非 win32 不注册，并写一条日志 |
| 心情判断的内存增长 | 会话桶只增不删 | 超过 200 个丢最旧 50 个 |

### 三处登录态不一致（2026-11-13 补修）

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 监听登录了、活动没登录 | 监听用独立档案 `data/browser-profile-listen`，手动扫码只写监听档案，不写 `sessionStore`；登录/活动同档案但不同端口，活动开着头再登录会抢档案锁 | 新增 `browser-hub.js`：全项目一个 Chromium、一份 `data/browser-profile`、统一端口；登录/活动/监听/值班各开自己的标签页，停止只关自己的标签；`data/platform/browser-hub.json` 给值班独立进程发现用 |

### 临时浏览器档案泄漏（2026-11-13 补修）

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| `%TEMP%\fish-douyin-*` 堆积 | 调用方没传 `profileDir` 时 `launchBrowser` 用 `mkdtemp` 建一次性档案；值班结束 `taskkill /T /F` 强杀，`closeBrowser` 跑不到；11–12 日累积 111 个、约 10.24 GB | 登录空配置回退固定 `data/browser-profile`；`cdp.js` 登记临时目录并在正常关闭/进程退出时清理；新增 `temp-profiles.js`，适配器 `connect()` 与值班服务端启动时清扫 12 小时前的残留（先 rename 再删，占用中自动跳过） |

## 二、故意留着的（有记录，不是忘了）

| 事项 | 为什么先不做 | 影响 |
| --- | --- | --- |
| 按会话关闭人格 | DSH 的 `systemPrompt` 是全局的，按会话过滤需要额外机制 | 装了就所有对话都是它；README 已明说 |
| 人情味的「疤」（拒绝留痕） | 需要新记忆类型 + 注入策略 + 迁移 | 暂时靠提示词里的「顶回去」 |
| 嘴硬配额（一天一次） | 需要决策层计数器 + 提示词联动 | 暂时靠提示词约束 |
| 值班 CLI 路径与 provider 硬编码 | 要等 DSH 开放更稳的宿主会话接口 | 换版本/换 provider 的用户起不了值班 |
| `dataDir` 配置项 | 全仓库路径都走 `fromRoot()`，真要支持得动所有模块 | 目前改了 `dataDir` 无效 |
| `prompts/` 运行时可编辑会脏 git | 需要「模板 + data 覆盖」双份机制 | 用户改过剧本后 `git status` 会变脏 |
| 卡片图片生成接入 | `image/card.js` 目前只被测试用到；本轮先保留（模板/深色卡片测试仍覆盖） | 属未接线功能，后续要么接 GUI，要么连测试一起删 |
| 跨平台（mac/Linux） | 抖音自动化 + 豆包 + 剪贴板全依赖 Windows | 已加平台守卫，非 Windows 上这些能力不注册 |
