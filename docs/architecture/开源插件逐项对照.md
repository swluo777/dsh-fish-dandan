## 四、明确剔除 / 必须设闸

1. **不引入任何 AGPL / NOASSERTION / 无 License 的代码**：Self Learning（AGPL-3.0，且衍生自 AGPL 的 AstrBot）、fish-memory（自定义非 OSI 许可）、private_companion 与 blue-fish-archive（`license: null`）、billion-context（MIT + 附加署名）。**只借参数与机制，不复制源码/词表/素材**；思路来源已登记本文件。
2. **不让模型自改人格**：`soul_update`、Self Learning 的自动应用策略、Letta core memory 自编辑，全部与「人格锚定不可自改」冲突；soul-md 自己都承认写入「不保证自动发生」。我们保留 `buildEvolvedSection()` 这种「只描述可变化倾向」的安全成长。
3. **不引入重量级外部依赖**：Embedding / Faiss / 图数据库 / PostgreSQL / LLM 常驻调用。保留 `dailyReview({summarizer})` 注入位但默认走确定性归纳，零外部请求、可单测。
4. **不做以本人账号自动评论 / 私信 / 长期 Cookie**：抖音 README 原文「可能违反用户协议，账号风险自负」；B站版已造成真实社区污染。`autoExternal=false` + `requireApproval=true` + pending 队列是正确姿态，06/07 也只做只读采集 + 本地日报。
5. **不叠第三方上下文压缩器**：会禁用宿主原生 compaction 且与竞争引擎冲突；我们只做自己记忆库内的有界注入与分层摘要。
6. **不混用两套 CC 协议素材**：表情包 CC BY-NC 4.0 与档案馆 CC BY-NC-SA 4.0 不兼容。现有 `assets/icon.png`/`avatar.png` 来自 CC BY-NC-SA 4.0 的 `fornarwhal/deepseek-whale-girl-icon`，署名见 [THIRD_PARTY_NOTICES](../legal/THIRD_PARTY_NOTICES.md)。

## 五、还没做（诚实登记，按优先级）

| 优先级 | 缺口 | 为什么暂缓 |
|---|---|---|
| 高 | **具体平台适配器（06/07）** | 05 只做基座是既定边界；`routeOutgoing` 缺主动发起路径（`decideNext()` 的 plan 没有 `conversation`），所以「主动发消息」目前仍不会发生。要先补这条再谈粘人 |
| 高 | **主动行为可解释台账** | `scheduler.canWake()` 只返回 bool，被拒原因只有一行日志；应改成 `{ok, reason}` 并在 GUI 展示 |
| 中 | 事实键 / 「已被取代」版本关系 / 单值修订 | 要动 `memories` 表结构，需一并补迁移与测试 |
| 中 | 断言层、提及反馈回写、`mention_policy` 四档、拟人化措辞 | 需要「模型提到了哪条记忆」的回执链路，当前没有 |
| 中 | 按人差异化遗忘速率、imprint 刻骨例外 | 需要亲密度真实参与 `decayFactor`，本轮只做了展示层六档 |
| 中 | 入站防抖 / 收尾沉默 / 当轮一次性事实块 | 依赖宿主 pre-step 能否拦住模型调用，需真机验证语义 |
| 低 | 表情包、六态 JSONL 事件总线、桌宠联动 | 属于可视化层，不阻塞「在 DSH 里对话」这个目标 |
| 低 | 0-token 硬过滤、谷时时段、`DRAFT_ONLY` 草稿语义 | 等具体适配器落地时一起做，否则只是空契约 |

## 六、结论

**「在 DSH 里跟大肥鱼对话」这件事已经闭环**：人格锚定段（`systemPrompt.section`）在所有会话生效 → 记忆上下文（`systemPrompt.context`）每步带人物卡与相关经历 → 对话中值得记的话自动入库 → 主页能看到它的性格/情绪/心情。新用户走「从零配置」五步（可 AI 一键生成）即可开始。

**真正的差距不是「缺功能」，而是「缺主动发起路径」**：调度器已经比多数竞品更保守完整，但 `decideNext()` 产出的 plan 不带 `conversation`，`routeOutgoing` 就不会被调用，所以它还不会主动找你说话。这是 06 之前必须先补的一根线，且补的时候要保持 `requireApproval` 不放开。
