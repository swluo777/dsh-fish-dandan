# 13 · dsh-bili-whale 拆解（它为什么像人）

> 用户点名研究 [Alterssss/dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale)（MIT）：它刷 B 站会 @ 主人、会主动回复私信，非常拟人。
> 这份是读源码后的笔记，只借鉴思路。

## 一、它到底在跑什么

```
插件宿主
  └─ 每 60 秒心跳（ctx 定时器）
       ├─ 到作息窗口 → 掷骰子（30% 今天不想看，直接跳过）
       │    └─ 叫醒一个 DSH 会话，投一段「你醒了」的剧本（wakePrompt）
       ├─ 私信监听（60 秒一轮，空闲退避翻倍到 15 分钟）
       └─ 评论/@ 监听（默认关，开了每 60 秒一次）
```

**关键：它不是脚本翻页，是"叫醒一个会思考的会话"，把一天的剧本交给它。**
会话本身由宿主 `controller.create({sessionId, cwd})` 创建/复用，`controller.prompt({sessionId, content})` 投递消息——和我们的 duty 会话是一回事，区别是我们用 spawn 子进程，它用宿主会话。

## 二、像人的四个零件

### 1. 生物钟 + 随机开摆
- 固定作息窗口（默认 20:00–24:00），窗口内随机一个时刻醒；
- `skipChance 30%`——今天不想看也是活人行为；
- 沉默衰减：3 天没互动开始降、7 天归零（"她向你索取耐心"）。

### 2. 两本日记
- `whale-diary.md`（给主人看） + `whale-diary-private.md`（私人，写「偏好校准」——主人喜欢什么、讨厌什么）；
- 每次唤醒第一件事：**读日记恢复记忆**（`先读本地日记恢复记忆，不要将旧会话未确认事项当成已完成`）；
- 每次收工最后一件：写日记。

### 3. 判据式行为，不是任务清单
唤醒剧本不说"看 5 条"，说判据：
- 收藏：三个月后还想点开 / 说得出为什么（≥6 字）/ 同类 ≥2 条要 `--better`；一天 ≤3 条，同视频 30 天一次；
- 分享：**只对第一名考虑**，判据是「值不值得占用主人一次注意力」；
- 分享渠道二选一（私信 or 评论区 @），剧本里明说"不要走另一条路"。
- 主动 @ 前还有一道「疑似 AI 评论」闸：先采评论由模型判，疑似比例 ≥30% 就暂缓分享（防止自己的号被判定 AI 刷屏）。

### 4. @ 主人的两条路
- 私信：`dm --share <分享内容 + 视频链接>`；
- 评论：`comment --share`（在视频评论区 @ 主人）；
- 主人 @ 它 → 它读消息、核实原帖，**只回主人**（配置 `onlyOwner`），用 `notify` 推总结；
- 分享额度：默认一天最多 3 次，配额账本 `quota.json` 计数，撞限流就停手。

## 三、主动回复私信怎么做的

1. **轮询而不是长连接**：`dmIntervalSec` 默认 60 秒一轮（`pollDelay` 空闲退避：60s → 翻倍 → 15 分钟封顶，有人说话立刻回 60s）。
2. **只回主人 / 只回 @ 她的**（`scope`），其他人先入队等主人在设置页批准——**不擅自对外说话**。
3. **同一个人 30 天只回一条**（防骚扰）。
4. 请求保护层 `tools/lib/traffic.mjs`：全局请求间隔 600ms、跨进程共享、单并发；读 600/时 3000/天；写 12/时 30/天；两次写至少 120 秒；撞 412/429 全局暂停 5/10/20/30 分钟并尊重 `Retry-After`；防重复发送（指纹 + 24h）；账本损坏直接拒绝请求，不静默重建。
5. 回复不是秒回：收到 → 入队 → 投给会话 → 会话生成 → 发送；这中间自然有延迟，像人。

## 四、会话投递（session-delivery.js）的细节，值得抄

- 会话 id 持久化到 `whale-session.json`，重启复用；
- **进程启动后第一次投递一定重注入完整人设 + 日记恢复指引**（防止重启失忆；代价是多花 ~1000 字）；
- 人设指纹去重（同一会话内人设没变就不重复注入，省 token）；
- 会话轮换（`sessionRotateDays`）——防止一个会话无限长；
- 可靠交付：`requestId` + `pendingRequest`，投递失败保留重试状态；成功后清掉；
- 投递串行（`tail` 队列），不会并发打架。

## 五、我们能直接借的（对抖音）

| 它的做法 | 我们抖音版的落地 |
| --- | --- |
| 生物钟 + 30% 开摆 | 已有"不限时、不自动跑"；可加"每天最多醒两次 + 随机跳过"作为默认 |
| 两本日记 | 我们有记忆（anchor/trait/episodic），可以加"私人日记"（偏好校准） |
| 判据式剧本 | 值班指南已经是"自由活动"，可补"值不值得占用主人一次注意力"这种判据 |
| @ 主人（私信/评论） | 我们已有私信；可以加「@ 主人」语义：分享时私信主人，带作品链接 |
| 私信监听 60s + 空闲退避 | 我们还没做，这是下一步（文档 12 已设计） |
| 只回主人 / 他人入队待批 | 我们该做：主人以外的人发私信 → 先入队等主人批准再回 |
| 请求保护层 | 抖音我们走 CDP 操作，节奏更慢；可借"写冷却/预算/撞限停手"的思路 |
| 会话投递 + 人设指纹 | 我们 duty 是 spawn 子进程，每次冷启动；可改成宿主会话（更快更稳） |

## 六、一句话总结

它像人，不是因为提示词写得好，是因为它有：
**自己的时间（生物钟）、自己的记忆（两本日记）、自己的判断（判据不是任务）、自己的边界（只回主人、额度、风控）。**

我们缺的正是"时间 + 监听 + 边界"这三样。前三样（人格、记忆、说话）我们已经有底子了。
## 七、我们照它做了什么（2026-11-12 晚）

按用户要求「照着他做，web 端一并改」：

| 文件 | 作用 |
| --- | --- |
| `src/platform/douyin/inbox.js` | 读消息浮层（`.imContainer` + `.conversationConversationItemwrapper`）、按名字点会话、发消息、回复兜底 |
| `src/platform/douyin/listen.js` | 轮询一次收件箱、新消息入队（只认主人 / scope=all）、已读游标与队列持久化（`data/state/douyin-inbox.json`）、退避计算 |
| `src/platform/douyin/listener.js` | 共享浏览器里的常驻监听标签页（档案 `data/browser-profile`、统一 hub 端口）轮询；打开即暂停/静音视频，3 秒起步、失败退避到 30 秒、有新消息立刻回到最短间隔 |
| `src/platform/settings.js` | `douyin.listen.enabled / scope(owner/all) / ownerName / intervalSec` |
| `src/platform/douyin/index.js` | 适配器新增 `inbox` 接口，启动即挂监听，卸载即停 |
| `src/gui/api.js` | `GET /platforms/douyin/inbox`、`POST /platforms/douyin/inbox/decide`（approved / ignored） |
| `src/gui/web/index.html` | 平台页新增「抖音私信」卡：监听徽章、监听状态与待回队列、监听设置（开关、只回主人/所有人、主人昵称、间隔） |
| `duty-server` | 新增 `douyin_dm_send(to, text)` 主动私信；可发给主人或想找的人，但工具硬限频（10 分钟/条、每小时最多 2 条）；值班不读私信队列，队列归监听器独占 |

### 边界（照它的原则）

- **只认配置的主人**：默认 scope=owner，只认配置的 `ownerName`；改成 scope=all 会把其他人也收进队列，但陌生人只排队给主人看，不自动回复。
- **回复前读上下文**：监听用 `peekThread` 读最近一段对话，再走「点会话 → 输入 → Enter」发送；遇到验证就返回原因、不硬来。
- 监听自动回，值班不再消费队列；新消息到达时旧的 `approved` 标 `superseded`，每次只回最新一条。发送成功才写 `answered`；失败/防刷中保留，下一轮再试。
- **不做高频轮询**：30 秒下限、空转退避、失败翻倍。
- **重启不失忆**：队列和已读游标落盘，重启后接着用。

### 已知限制

- 抖音网页的消息浮层结构会变，选择器集中写在 `inbox.js`，坏了只改一处。
- 值班只主动发，不再回队列；监听是唯一的被动回复入口。是否该回只看当前会话最后一条是谁发的，最后一条是自己发的就跳过，不用发送记录猜回音。
- 监听器的 headless 浏览器与刷流/围观窗口分开，但共用登录态（每次启动重新注入 Cookie）。
