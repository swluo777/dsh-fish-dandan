# 24-行为执行器与自动策略设计

> 状态：调度语义已实现（2026-11-14）；其中「专注创作」的画图实现已被
> [`26-专注创作手绘画图重做设计.md`](./26-专注创作手绘画图重做设计.md) 整体取代，
> 旧 `code-art / journal-plan / hand-drawn / parts` 内容仅作历史记录，不要照搬。
>
> 目标：把「行为与调度」从「计划器 + 审批壳」改成「状态 / 策略 / 活动」三层，让自主探索、社交互动、专注创作真正可执行、可停止、可解释。

## 1. 为什么改

旧实现里：

- `planFor()` 只给 `kind/text/external/tools/requiresApproval`，点「执行」时没有具体平台、目标、收件人或素材；
- `platforms.execute()` 只认 `plan.conversation`，当前计划没有这个字段，所以只会返回「05 基座没有具体平台」；
- 待确认队列只在内存里，插件重载就丢；
- `/pending/approve` 先把条目取出再执行，执行器返回 `ok:false` 时不会放回；
- `create` 被归成 `external`，但它实际上是本地动作；
- `duty` 的轮次只有 `why` 一个字符串，没有 owner/task，无法判断「这轮是谁拉起的、结束后该不该停」；
- 平台页的 `autoWake` 和行为调度的自主唤醒是两套触发源，可能重复拉起刷流。

## 2. 三层模型

### 状态 state

它现在想做什么：`sleep / rest / explore / social / create`。只表达倾向，不等于正在执行。

### 策略 policy

每类动作在触发时怎么处理，三档：

| 档位 | 行为 |
|---|---|
| `auto` | 触发即启动执行器，不进待确认 |
| `ask` | 进待确认，卡片带具体载荷；主人点执行才跑 |
| `off` | 触发只记调度日志，不进待确认，不执行；等价于主人点了「不执行」 |

默认迁移为 `ask`，保留旧行为；新装也可以改成 `off`。

### 活动 activity

当前真正在跑什么：

```js
{
  id,
  kind: 'explore' | 'social' | 'create',
  label: '自主探索' | '社交互动' | '专注创作',
  status: 'running' | 'stopping' | 'done' | 'failed' | 'cancelled' | 'skipped' | 'interrupted',
  trigger: 'state' | 'approval' | 'manual' | 'chat',
  detail,
  startedAt,
  canStop,
  result
}
```

同一时间只允许一个活动。GUI 读 `decision.getInternalState().activity`，停止走 `POST /decision/activity/stop`。

## 3. 三类动作

### 3.1 自主探索

- 文案：`去抖音逛一圈，把有意思的东西记下来`。
- 前置：`browse.enabled`、抖音登录态 connected；任一不满足就 `skipped`，并把原因写成「去平台页打开哪个按钮」的可执行提示。`platforms.enabled` 不再拦本地刷流/社交，只负责适配器连接与出站。
- 执行：复用 `duty.start('自主探索', { task: 'explore', owner: 'explore' })`；行为页的「立即触发一次」也走同一轮值班。
- 结束：值班 `settle` 即活动结束；记忆仍由 `duty.importEvents()` 写入，不重复写。
- 停止：`duty.stop()`；状态 `stopping` → `cancelled`。
- 手动「立即触发一次」：`task: 'explore'`、`owner: 'manual'`；与自主探索同源同结束，但不受策略三档和频率上限限制。
- 停止后给同类动作一个冷却时间，避免刚停又自动开始。

### 3.2 社交互动

- 文案：`找主人聊两句，看看对方在忙什么`；目前只做主人，不做熟人。
- 前置：`browse.enabled`、`actions.dm`、`listen.ownerName` 非空、登录态 connected；任一不满足就 `skipped`，并给出「去平台页打开哪个按钮」的提示。`platforms.enabled` 同上，不拦本地社交。
- 执行：起受限值班任务 `task: 'social'`；工具清单只保留：
  - `douyin_status`
  - `douyin_dm_context`
  - `douyin_dm_send`
  - `douyin_memory`
  - `douyin_finish`
- 提示词明确只找主人、发 1-2 句、发完结束；`douyin_dm_send` 在 social 任务里只接受 owner/主人/省略，拒绝其他收件人。
- 频控：复用 `dm-limiter`（两次至少 10 分钟、每小时最多 2 条）；行为调度本身还有最小间隔和每日预算。
- 结束：收到成功的 `say dm` 事件后标记 `socialSent`；如果这一轮 `round.owner === 'social'`，自动 `duty.stop()` 强制结束这一轮。
- 不误停别人的轮次：如果值班已经在跑，且 owner 是 `manual / explore`（旧轮次可能记为 `autoWake`），社交互动直接跳过，报「抖音正在忙」。
- 停止：如果消息还没发出，记 `cancelled`，不写「已发」记忆；如果已经发出，记 `done`，停止不撤销已发消息。

### 3.3 专注创作

> 旧版实现记录（`journal / hand-drawn / parts`）已整体作废，不要照搬。当前实现见
> [`26-专注创作手绘画图重做设计.md`](./26-专注创作手绘画图重做设计.md)：35 张手绘角色底稿 + 浅色 Canvas 场景合成，运行时本地渲染；模型可给场景意图，但坐标与绘制都在本地。

- 文案：`画一张图放桌面`；不做视频。执行时优先挑一张表情包当参考；表情包库空时退到形象库主形象；两者都没有才自由发挥。
- 不调用豆包深图、`painter` 或任何付费生图 API。
- 执行：
  1. 从本地表情包库按当前心情/创作欲/语义挑一张；没有可用表情包时读形象库主形象（优先 `primaryImageId`），库空才自由发挥。
  2. 用 HTML 程序化生成 1080×1440 页面；`journal` 用 Canvas2D 按参考图重画，其他版式仍用 HTML/SVG。参考图在 `journal` 里只进入 Canvas 的 `DATA.reference`，不直接把原图 `<img>` 贴进画面；参考图缺失时走空库自由场景，参考图解码失败时画一张“这张参考没读出来”的空白手账，不再退回鲸鱼。
  3. 用共享浏览器新标签打开 HTML，`Page.captureScreenshot` 截全图。
  4. PNG 写桌面；HTML 留 `data/creative/`；索引写 `data/creative/index.json`。
- 模板统一为 `journal` 手帐纸，不再按 seed 在旧版式里抽签；`collage/comic/fullbleed` 只保留为历史样式，不参与生成。
  - 4 种纸张：横线、方格、牛皮纸、白纸；不同纸张有不同 inset、倾斜、标题位置和底色；
  - 8 套配色：深海底色 7 套 + 暖纸色 1 套，每套带 `paper / paperInk`；
  - 表情包只作为“今天画什么心情/什么图案”的引子，不再把带对白的表情包原图描进手稿；形象库的单角色图没有大段文字，仍可参考重画；
  - 4 个空库场景：`whale` 鲸鱼、`coral` 珊瑚、`night` 夜海、`sketch` 线稿；它们现在通过 `plan.scene` 真正进入 `drawSceneAtmosphere()`，不再只是历史字段；
  - 标题从心情池 + 人格/记忆池生成，场景标题（`SCENE_TITLES`）不再无条件覆盖；副标题避开标题中心词，边注/引用/副标题互不去重；
  - 纸张、构图、场景、版式由 seed 和心情错开，避免连续几张一样；
  - 不再读取上一张的 `layout`，也不会再走到 `collage/comic/fullbleed` 分支。
- 先写场景，再画：`src/decision/journal-plan.js` 的 `buildArtPlan()` 是纯本地函数，先决定 `theme / structure / mood / creativeUrge / scene / composition / layout / objects / relations / title / subtitle / quote / notes / annotations / motifs`，再交给 `hand-drawn.js` 的 Canvas 画。主题不是固定图案表，而是 20 个生活片段（可乐罐、炸鸡桶、电脑桌加班、键盘、枕头、手机、杯子、书、花、雨伞、月亮、鱼缸、爱心、星星、单画脑袋、太阳、云雨、眼泪、炸鸡+电脑桌、书+鱼缸）；`structure` 是 `stack / desk / duo / peek / scatter / portrait` 六种关系骨架，`objects` 是白名单对象（头、身体、桌子、电脑、椅子、可乐罐、杯子、炸鸡桶、键盘、枕头、手机、书、雨伞、鱼缸等），`relations` 记录 `on-top / sit-at / face / peeking / beside`。
- `buildArtPlan()` 用最近 5 张 `index.json` 的 `plan.theme` 去重，再按人格标签、记忆兴趣、心情带和创作欲打分；同一实例连续创作会换主题，不再每次只画鱼/星星/月亮。页边不再固定撒星星/爱心/云，只有场景对象少于两个（例如只画一个脑袋）时才补一个小记号；`render()` 把 `plan` 交给 `journalArtMarkup`，并把 `{ theme, structure, scene, composition, layout, objects, relations, density, messiness }` 写进 `index.json` 和返回值，方便之后复盘“今天为什么画这个”。
- `buildSceneObjects()` 现在真的执行构图：`left/right` 平移对象，`close` 放大并下移，`small` 缩小并下移，`mirror` 把 `x = 1 - x`；`annotationSlots()` 同步平移/镜像，避免边注和对象脱节。`buildLayout()` 产出 5 个版式变体、边注左右、引用左右和标题对齐，`journalCss()` 用这些值改变纸张 inset、倾斜、标题位置、字号、胶带位置、引用位置和边注位置。
- Canvas 的 `drawPlanScene()` 按 z 顺序画对象，再画场景气氛、草稿线、纸纹；角色不再直贴 `assets/character/dandan/parts/{front,head,side,back}.png`，而是 `buildSketchSprite()` 从 `front.png` 在页面加载时重画成线稿层 + 半透明淡彩层：下采样取主体 mask、去透明底白边、腐蚀/最大连通域/膨胀、裁主体包围盒，再在 640px 画布上按亮度梯度取边、按饱和度/亮度上淡彩，线稿带 5.5% 断线和 1.2/1.4px 复线。`head` 模式从 `front.png` 裁胸像并做底部 20% 渐隐，避免方贴纸边。`drawSketchCharacter()` 负责按对象高度画 wash/line；角色尺寸按对象 scale × 1.4 放大，保证脸部细节可读。四张 PNG 只保留为素材源/未来扩展，plan 路径不再调用 `drawCharacterPart()`；失败才回退 `drawSelfHead/drawSelf` 合成路径。
- `plan.title/subtitle/quote` 仍保留在 plan 里供测试/记录，但渲染最终标题/副标题/引用/边注全部取 `journalCopy`；`plan.notes` 被 `journalCopy.notes.slice(0,2)` 覆写，`plan.annotations` 清空，避免同一句边注既在纸边又挂在箭头上重复。
- 不再用旧固定图案当 journal 的回退：`plan` 缺失/异常时 `drawPlanFallback()` 画一张“今天没想好”的手稿，而不是回到鱼/星星/月亮模板；旧 `drawDoodleScene` 的固定 motif 代码只保留在历史函数里，不参与当前入口。
- `journal` 的手绘页：Canvas2D 里用中心线采样、沿法线低频噪声位移、压力变宽、两遍墨线、闭合线拆 1–2 笔、错位填色、排线和纸纹；标题、副标题、边注、引用、页脚和英文页眉都优先用项目自带 `assets/fonts/zcool-kuaile/ZCOOLKuaiLe-Regular.ttf`（OFL-1.1，页面 `@font-face` 从项目内加载，不依赖用户装字体），再回退 `KaiTi/cursive`；所有正文逐字歪斜、大小不一，标题最多两行，9 字以内尽量一行；有标点时按标点断，无标点时避免拆开“海底/鲸鱼/手稿”等常用双字词。字体只是站酷快乐体骨架，所以 journalBody 还插入一张隐藏 SVG `feTurbulence + feDisplacementMap` 滤镜 `kid-ink`，给标题/正文/页脚的文字边缘加轻微墨迹抖动，避免看起来像干净印刷体；表情包不再进入 `DATA.reference`，只由 caption 选情绪。
- `characterData()` 只读形象库缩略图/主形象，按 `primaryImageId` 取主形象；角色标签命中蛋蛋初始形象时，`characterPartAssets()` 额外把 `assets/character/dandan/parts/{front,head,side,back}.png` 以 `file://` URL 挂到 `character.assets`，由 `journalArtMarkup` 白名单放行，不进 base64、不把 7MB 原图塞进 HTML。当前 plan 角色只用 `front.png` 作为 sketch 源图，`head` 也从 `front` 裁胸像；`side/back/head.png` 保留为后续姿态扩展素材，不再直接贴进画面。内置 `origin=release` 的三视图仍用 `crop = {x:0.03, y:0.02, w:0.345, h:0.64}` 取左侧正面视图（留到鲸鱼尾巴末端），本机上传不裁；三视图是白底浅网格，`drawSketch` 会先取“有颜色或偏暗”的像素，再补回被主体包住的白色围裙/袜子，避免把“Front / Details”和网格一起画进来。有表情包时只借 caption 选情绪/图案，没有表情包才用形象库角色参考。

- `index.json` 每条新增 `layout / scene / treatment / title`；`render` 返回值也带 `layout / scene / treatment`。`prepare()` 仍只暴露 `stickerId / theme`，不提前锁死版式。
- 空库时 `journal` 会在纸上画一张可见的心情涂鸦；有形象库角色时按角色重画。`collage/comic/fullbleed` 不再参与生成。
- 结束：截图成功、文件落盘 → `done`；截图失败 → `failed`，但保留 HTML 路径，不谎报成功。
- 停止：取消当前生成、关闭标签页、不写 PNG，状态 `cancelled`。
- 预期：代码画图是程序化海报/插画，不是生图模型那种写实。

## 4. 计划载荷

`planFor()` 保留 `kind/text/external/tools/requiresApproval` 兼容字段，同时新增：

```js
{
  kind,
  text,
  scope: 'local' | 'platform',
  executor: 'douyin-round' | 'social-dm' | 'code-art' | null,
  payload: { ... },
  preview: { title, detail, ... },
  policy: 'auto' | 'ask' | 'off'
}
```

没有执行器的计划不显示「执行」按钮。`create` 的 `scope` 是 `local`，不再用 `external` 兼作审批开关。

## 5. 待确认队列

- 只有 `ask` 档才进队列。
- 队列落盘到 `data/state/pending.json`，重启可恢复。
- 条目带 `executor / payload / preview`，卡片能说清楚要做什么、发给谁、用什么素材。
- 支持忽略、TTL（默认 30 分钟）、状态切换失效。
- `/pending/approve` 执行前取出，执行失败放回；不再出现「卡片消失、只留一条未执行记忆」。

## 6. 权限矩阵

| 动作 | 允许用抖音 | 登录态 | 私信主动 | 主人昵称 | 其他 |
|---|---|---|---|---|---|
| 自主探索 | 需要 | 需要 | - | - | - |
| 社交互动 | 需要 | 需要 | 需要 | 需要 | dm-limiter |
| 专注创作 | - | - | - | - | 本地表情包库可空 |

权限关闭时不启动；提示写清去「平台」页把「允许它用抖音」打开，再回来点「立即触发一次」。`platforms.enabled` 是适配器连接/出站开关，不拦抖音本地动作；手动触发也只认「允许它用抖音」，不绕过它。

执行器读的是整份平台设置：权限字段在 `settings().douyin.browse / actions / listen` 下，不是顶层 `enabled`。测试里的假适配器必须用同一嵌套形状，否则扁平假数据会把真实适配器的结构问题盖住。

## 7. GUI

行为与调度页：

1. 状态卡；
2. 「执行方式」：自主探索 / 社交互动 / 专注创作，每类三档；
3. 「它现在正在做」：有活动才出现，带强制停止；
4. 「等你点头」：只有 `ask` 档才有，卡片带具体载荷；
5. 「调度参数」：静默时段、每日总次数上限、随机抖动、最小空闲，以及每类动作的每日最多次数与间隔分钟；
6. 每类动作的「立即触发一次」：手动执行一次，不经过策略三档，也不占自动调度的次数；执行中该行按钮变成「终止」，走同一个 `/decision/activity/stop`，结束后短轮询恢复按钮。

平台页只保留活动状态和停止；单次开始统一在行为页的「立即触发一次」，三类动作各一个入口，和活动状态共用执行器，正在跑时按钮禁用。

## 8. 自动入口去重

- 行为调度是唯一自主触发源；平台页不再保留 `autoWake` 独立触发器。
- 平台页只保留权限：`允许它用抖音`、登录态、点赞/评论/私信等能力位；不再决定“它会不会自己挑时候去”。
- 自主探索只在行为页「自主探索」策略为 `auto` 时执行；`ask` 进待确认，`off` 不消耗总预算。
- `ActionRunner` 同一时间只允许一个活动，作为最后一道去重。

## 8.1 频率配置

调度参数由行为页统一设置，落盘到 `data/state/scheduler.json`：

| 参数 | 默认 | 作用 |
|---|---|---|
| `dailyBudget` | 8 | 三类主动动作总共的每日上限；休息/发呆不占 |
| `quietHours` | 23:00–07:00 | 静默时段，不主动醒 |
| `minIdleMs` | 10 分钟 | 任意两次主动行为的最小空闲 |
| `jitterRatio` | 0.35 | 唤醒时间的随机抖动 |
| `actionLimits.explore` | 3 次/天，90 分钟 | 自主探索的单类上限与间隔 |
| `actionLimits.social` | 2 次/天，120 分钟 | 社交互动的单类上限与间隔 |
| `actionLimits.create` | 2 次/天，120 分钟 | 专注创作的单类上限与间隔 |

- 先过总闸，再过单类闸；单类设 0 = 该类不自动跑，手动执行仍可用。总闸只统计三类主动动作，休息/发呆和关闭档不占。
- 询问档触发也占一次单类次数，避免同一件事反复弹待确认；关闭档不占。
- 单类计数按本地日期滚动，重启后从 `scheduler.json` 恢复，不会重启即重置。

## 9. 失败与重启

- 执行器返回 `ok:false` 时，`ask` 档把条目放回队列。
- 插件重载时，如果活动状态是 `running` 但没有活着的轮次，标记 `interrupted`，不假装还在跑。
- 值班标签页被手动关闭时，`duty` 的 tab watch 停止这一轮，活动状态随之失败/取消。
- 真实私信回归不自动执行；需要主人点头后再发。
