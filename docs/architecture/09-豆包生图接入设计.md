# 09 · 豆包生图接入设计（让大肥鱼自己画画）

> 状态：**后端已实现，设置页入口暂隐藏**（2026-11-11 设计，随后落地为 `src/image/doubao.js` + `src/image/doubao-ui.ps1`；网页端 `SHOW_PAINT_UI = false` 时不渲染作图卡片，也不请求作图状态）。
> 依据：最初的实施方案文档（内部资料，未随仓库分发）的 PHASE 2「形象工程」与 MODULE 06「绘画与创作」，
> 以及本次对火山方舟官方文档的调研。那份方案里的 `dsh-doubao-painter` 只有一行表格描述、没有设计文档，
> 且正文写的是 Python 技术栈——与本仓库「纯 Node ESM、零依赖」冲突，这里按仓库现状改。

## 一、目标（两步走）

1. **形象工程**：先给本鱼一个固定形象——三视图 + 头像，之后换头像、改资料都能保持同一张脸。
2. **自己画画**：创作欲/灵感上来时，本鱼能自己调生图工具画一张，落盘、写进记忆、以后还能拿出来看。
3. 再往后：表情包库（按情绪检索、发表情），和「发消息」一起做。

## 二、接口（已核实官方文档）

- 入口：`POST https://ark.cn-beijing.volces.com/api/v3/images/generations`（cn-beijing）。
- 鉴权：`Authorization: Bearer $ARK_API_KEY`。Key 在火山方舟控制台的 API Key 管理页取。
  **本插件只读环境变量或 DSH 凭证层，配置里只存变量名，不存值**；报错信息不整包打印响应头。
- 文生图与图生图**同一个端点**：不传 `image` 是文生图；传 `image`（URL 或 `data:image/png;base64,...`）就是图生图。
- 关键参数：
  - `model`：如 `doubao-seedream-5-0-pro-260628`；
  - `prompt`：中文 ≤300 字较稳；
  - `size`：档位（1K/1.5K/2K…）或 `宽x高`；出组图用 `sequential_image_generation=auto` + `max_images`；
  - `response_format`：**必须 `b64_json`**（默认 `url`，24 小时失效，本机要落盘）；
  - `watermark`：默认 true，本地用设 `false`；
  - `output_format`：png/webp/jpeg。
- 计费：按成功出图张数（`usage.generated_images`），IPM 500。
- 内容审核：平台默认护栏；组图里单张没过审会写在 `data[].error`，不影响同批其他张。

### 模型与价格（2026-11 控制台口径）

| 模型 ID | 分辨率 | 单价 | 用途 |
|---|---|---|---|
| `doubao-seedream-5-0-flash-260915` | 1K/1.5K/2K | 0.12 元/张 | 日常画画、表情包批量 |
| `doubao-seedream-5-0-pro-260628` | 1K/1.5K/2K | 0.3 元/张（2K 方图超像素档 → 0.6） | 形象三视图、头像定妆 |

## 三、本机实现方案

### 1. 目录与落盘

```
data/images/
  profile/            形象设定图（定妆照、三视图）——长期保留
  2026-11-11/         当天随手画的
    <时间戳>-<hash>.png
```

- 一律 `b64_json` 拿 Buffer 直接写文件，写完校验 PNG magic 与大小（<12MB）；
- `data/` 整体已被 `.gitignore` 挡住，图片不会入库；
- 每张记一行台账 `data/images/index.jsonl`：时间、prompt、模型、尺寸、hash、费用估算、来源（自主/网页触发）。

### 2. 模块与工具

新增 `src/image/`（纯 ESM，零依赖，用内置 `fetch`）：

| 文件 | 职责 |
|---|---|
| `src/image/ark.js` | 组装请求、鉴权、错误分类、指数退避、费用估算 |
| `src/image/store.js` | 落盘、台账、按 hash 去重、按日期/标签查询 |
| `src/image/prompt.js` | 形象设定词（发色/瞳色/鳍耳/尾巴/围裙…）+ 风格词，固定 seed 思路 |
| `src/image/index.js` | 对插件暴露 `paint()` / `variant()` / `list()` |

对模型暴露的窄工具（与抖音一样由宿主注册）：

- `paint`：`{ prompt, kind: 'free' | 'profile' | 'sticker', size? }` → 生成并落盘，返回本地路径与一张缩略图；
- `variant`：`{ refPath, prompt }` → 图生图（换装/改姿势/做表情包，保持同一张脸）。

### 3. 成本与风控（宿主强制）

- 每日出图上限（默认 8 张/天）+ 最小间隔 30 秒，超了直接拒绝并说明；
- `size` 白名单只给 1K/1.5K，2K 要走显式确认；
- 429 指数退避；审核类错误（`data[].error`）**不重试**；
- prompt 先过本地 `safety.js`（密钥/路径/注入检测），再发出去。

### 4. 内容审核与合规

- 出图前：prompt 过敏感词与提示词注入检测；
- 出图后：审核失败的那张不落盘、不记账为成功；
- 形象素材：只用自己生成的图；外部参考素材按第四节许可处理。

### 5. 与「创作欲」的连接（M4）

决策层已有 `creativeUrge` 变量。取值越阈值 + 心情合适时，宿主给模型一次「你可以画点什么」的机会（和抖音值班同一套机制：起独立会话/或直接调工具），画完写一条第一人称记忆并落盘。

## 八、已固化：借用本机豆包客户端（2026-11-11 深夜）

用户机器上开着豆包 PC 客户端（Electron，`D:\Doubao\app\Doubao.exe`），希望「没有 API Key 的用户也能一键用上自己的大肥鱼」。实测走通了一条 UI 自动化路线，作为 ARK API 之外的零配置备用通道。

### 1. 实测流程（全部验证过）

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | UIA 按 pid 找豆包主窗口 → `SetForegroundWindow` | 拿到窗口句柄 |
| 2 | 点左侧导航「新对话」 | 进入空白推荐页 |
| 3 | 点左侧「更多」→「AI 创作」 | 进入画图模式，模型显示 `Seedream 5.0 Pro` |
| 4 | 点输入框 → 剪贴板 `Ctrl+V` 贴提示词 → 回车 | 开始生成 |
| 5 | 等 30–40 秒截图确认 | 「已生成圆形头像图片。」+ 图片 |
| 6 | 剪贴板放参考图（`Clipboard.SetImage`）→ 点输入框 `Ctrl+V` → 贴提示词 → 回车 | 图生图成功：「已按参考图的圆形头像风格改好」 |

产出：两张 Q 版大肥鱼娘头像（文生图一张、基于参考图改一张）。

### 2. 关键实现细节与坑

- **DPI**：PowerShell/Node 进程要 `SetProcessDpiAwarenessContext(-4)`（PER_MONITOR），否则 `Screen.Bounds`、`CopyFromScreen`、`SetCursorPos` 三套坐标系不一致，点击会偏。
- **坐标系**：UIA 的 `BoundingRectangle` 是逻辑坐标，截图/`SetCursorPos` 是物理坐标；一律用**窗口 rect + 相对比例**换算，别写死绝对坐标。
- **中文输入**：不要用 `SendKeys` 打中文（输入法会打架），用剪贴板 `Ctrl+V`。
- **UIA 不可用**：豆包 Electron 的内容区不暴露输入框/按钮（只有 Window/Document 两层），只能截图定位 + 坐标点击；左侧导航靠文字位置估算。
- **发送**：AI 创作页用回车发送（点蓝色发送按钮有时不生效）；对话框里也是回车。
- **取图（尚未解决）**：右键图片没有菜单、`User Data` 缓存里找不到落盘文件。待选方案：双击大图后看是否有下载、从渲染进程截帧裁剪、或抓包拿图片 URL。
- **用户打扰**：会占用用户当前豆包窗口与剪贴板；集成时要么开一个独立窗口，要么在后台静默前先征得同意。

### 3. 集成形态建议

插件里做 `src/image/doubao-ui` 适配层，对上暴露和 ARK API 相同的 `paint()` / `variant()` 接口：

- 有 `ARK_API_KEY` → 走 API（稳、可并发、可记账）；
- 没有 Key 但检测到本机豆包在跑 → 走 UI 自动化（零配置，但串行、慢、会打扰）；
- 两样都没有 → 明确告诉用户「先登录豆包或配一个 ARK Key」，不静默失败。

UI 自动化部分必须：单飞（同一时刻只跑一个生成任务）、每一步截图留证据、失败时把截图存到 `data/images/ui-fail-*.png` 方便排查。

### 4. 落地情况（2026-11-11 深夜，已固化进插件）

- `src/image/doubao-ui.ps1`：UI 自动化助手（detect / open-create / paint / screenshot），坐标按窗口相对比例，DPI 感知，输出 UTF-8 JSON。
- `src/image/doubao.js`：Node 封装。
  - 开关每次都现读 `data/state/platform-settings.json` 的 `image.doubao.enabled`，网页上一点立刻生效；
  - 单飞锁 + 失败截图 `data/images/ui-fail-*.png`；
  - 取图：读豆包 IndexedDB 最近的 `rc_gen_image` URL，**优先 `image_raw.png` 变体**，遇到 HEIC 会自动换模板再试，落盘 `data/images/<日期>/`。
- 设置：`platform-settings.json` 新增 `image.doubao.enabled`（默认关）。
- API：`GET /image/status`、`POST /image/paint`、`GET /image/list`。
- 网页：平台页新增「豆包做图」卡——**它只负责给许可**：一个开关 + 状态 + 一句说明 + 「它是怎么画的」折叠区（渐进式披露）。画什么、什么时候画由模型自己定，网页上不提供输入框和「画一张」按钮（用户 2026-11-11 明确要求）。
- 实测：打开开关后 `paint("画一只圆滚滚的蓝色小鲸鱼，Q版，白底，方形")`，24 秒返回 `data/images/2026-11-11/xxx.png`（2048×2048，1.3 MB）。
- 聊天工具：`doubao_paint`（描述 + 可选参考图 → 画一张）与 `doubao_paint_status`；许可打开后，用户在对话里说「画一张…」模型就能直接调。\n- 已知限制：会占用豆包窗口和剪贴板（开着开关时别同时手动用）；生成期间不能并发；豆包没装时接口明确返回「没找到豆包桌面版」。
## 九、检测修正：「没装」和「没开」是两件事（2026-11-12 凌晨）

用户反馈：界面显示「没装豆包」，其实只是豆包没运行。

- 根因：`doubao-ui.ps1 -Action detect` 只找**有主窗口的 Doubao 进程**，找不到就报「没找到豆包桌面版进程」，前端把这句话当成「没装」。
- 修法：新增 `Find-DoubaoExe`，按常见安装路径和注册表 App Paths 找可执行文件（本机实际在 `D:\Doubao\app\Doubao.exe`），detect 返回 `{ installed, detected }` 两项：
  - 有窗口：`installed:true, detected:true`；
  - 装了没开：`installed:true, detected:false, reason:'豆包没在运行'`；
  - 没装：`installed:false`。
- 新增 `-Action launch`：自动启动豆包并最多等 30 秒窗口出现；`paint()` 发现「装了但没开」时先自动打开，再继续画，不再直接报错。
- 前端：徽章分「没装豆包 / 豆包没开 / 未允许 / 已允许 / 正在画」；装了没开时按钮可用，提示「允许之后它要画的时候会自己打开」。
- 实测：本机状态从「没装豆包」变成 `installed:true, windowOpen:false, reason:'豆包没在运行（画的时候会自动打开）'`，`canPaint:true`。
