# 同类项目调研与借鉴

调研时间：2026-11-11。目标是回答三个问题：别人做了什么、怎么做的、哪些比我们好且值得搬进来。

> 说明：以下结论来自各项目公开文档/README 与二手技术分析。凡未直接读源码的地方，文中标注「二手」。我们自己的实现以仓库代码为准。

## 一、调研对象

| 项目 | 类型 | 为什么看它 |
|------|------|-----------|
| Stanford Generative Agents（Park et al., 2023） | 论文 + 参考实现 | 记忆检索三信号（recency / importance / relevance）的源头 |
| Mem0（mem0ai/mem0，Apache-2.0） | 开源记忆层 | 生产级写入管线：ADD-only、去重、混合检索 |
| Letta / MemGPT（UC Berkeley 起源） | 有状态 Agent 运行时 | core / archival 分层、Agent 自编辑记忆、sleep-time 整理 |
| AstrBot LivingMemory（AGPL-3.0） | 聊天机器人长期记忆插件 | 与我们的场景最接近：BM25+向量、TTL/衰减/强化、双通道总结、面板 |
| Zep / Graphiti | 时序知识图谱记忆 | 事实的“有效期”建模（二手资料） |

## 二、逐个拆解

### 1. Generative Agents：三信号检索

**做法**：所有观察进入一条 append-only 的 memory stream，每条带时间戳与 1–10 的重要度；检索分数是三个归一化信号的加权和：

```
score = α·recency + β·importance + γ·relevance
recency = 0.995 ^ 经过小时数（按最后访问时间）
importance = 写入时由模型打 1–10 分
relevance = 查询与记忆的向量余弦相似度
```

论文里三个权重都取 1；反思（reflection）在近期重要度累计超过阈值时触发，把零散观察总结成更高层的判断，再写回记忆流。

**比我们好的地方**：分数可解释、三项各司其职；重要度在写入时确定，读取时零成本；反思有明确触发条件。

**不足**：依赖向量与 LLM 打分；没有审计、没有分层、没有“不可改写的人格锚定”。

### 2. Mem0：ADD-only + 去重 + 混合检索

**做法（OSS v3，官方迁移文档）**：

- 写入是**单次 LLM 抽取 + 只 ADD**：新事实与旧事实并存，不覆盖、不删除；冲突靠检索时的时效排序解决；
- 写入前先取回 top-10 相关记忆做上下文，抽取后做 **MD5 哈希去重**；
- 检索是三路信号融合：向量语义、BM25 关键词、实体匹配；BM25/实体只做加权，不扩大候选集；
- 记忆按 user / session / agent 分域；时间元数据单独抽取（事件发生时间、是否持续、类型）。

**比我们好的地方**：明确把“写入去重”和“读取排序”分开；哈希去重比我们原来的前缀哈希严谨；分域清晰。

**不足**：实体/图能力在 OSS 版被移除，平台版才有；依赖向量库与 LLM，部署重。

### 3. Letta / MemGPT：core memory + 自编辑 + sleep-time

**做法**：

- **core memory** 是常驻上下文的可编辑块（human / persona / 自定义），Agent 通过工具自己改写；
- **archival memory** 是外部存储，按需检索回上下文；**recall memory** 存完整历史；
- **sleep-time compute**：空闲时由后台 Agent 整理、压缩、重组记忆，不阻塞对话。

**比我们好的地方**：把“常驻事实”和“可检索档案”分得很清楚；整理发生在空闲而不是对话中；记忆块可被多个 Agent 共享。

**不足**：让模型直接改 core memory，需要很强的锚定与审计，否则人格会漂；实现重。

### 4. AstrBot LivingMemory：和我们最像

**做法**：

- 对话 → LLM 总结 → 原子化为独立记忆（每条有 TTL、重要度、衰减曲线、强化机制）；
- 双路四模式检索：文档路 + 图路，各自关键词 + 向量，最后融合排序（BM25 + Faiss，RRF 融合）；
- 双通道总结：`canonical_summary` 与 `persona_summary` 分开，一个用于检索、一个用于提示词；
- 给 Agent 两个工具：`recall_long_term_memory` / `memorize_long_term_memory`；
- 面板：记忆管理、召回调试、图谱浏览；版本升级自动备份、事务删除、重建失败回滚。

**比我们好的地方**：检索融合更成熟；双通道总结的区分很实用；给模型主动召回/写入的工具；面板有“召回调试”；数据安全（备份/回滚）考虑周全。

**不足**：AGPL-3.0，代码不能直接搬进 MIT 项目；依赖 Embedding 服务与 Faiss；人格与记忆仍是两个插件拼接，没有统一的人格锚定与状态机。

### 5. Zep / Graphiti（二手）

把事实建模成带**有效期**的图边，能回答“当时是真的、现在过期了”。比纯向量更擅长时序冲突，但构图成本高、需要图数据库。我们暂不引入，只在数据模型上保留 `createdAt` 与不可变内容。

## 四、我们比它们好的地方

1. **人格与记忆是一体的**：人格锚定在系统提示词里，记忆只能通过 `evolvedTraits` 影响人格，不能改写身份；这几个项目里只有 Letta 的 persona block 接近，但它允许模型自改。
2. **全量审计 + 软删除**：每次写入、召回、锚定、复盘、合并都有记录，删除只做归档；LivingMemory 有备份，但没有逐条审计。
3. **零依赖可启动**：默认不需要 Embedding 服务、不需要向量库；`node:sqlite` 自带，装不上就降级 JSONL。
4. **主动行为是内生的**：五变量五状态决定“想做什么”，不是定时任务或外部清单驱动。
5. **安全闸门在写入前**：注入内容直接隔离，不参与检索与注入；其他项目多数只在提示词层做过滤。

## 五、已经搬进来的五项改进

| 借鉴点 | 来源 | 我们的实现 | 验证 |
|--------|------|-----------|------|
| 三信号加权 + 可解释分项 | Generative Agents | `scoreBreakdown()`，权重 `0.55/0.25/0.20`，返回 `parts`；面板显示“相关/重要/新鲜” | `test/memory.test.js`「返回可解释的三信号分项」 |
| 写入时自动评估重要度 | Generative Agents | `autoImportance()`：长度、人物、情绪词、承诺词、日期各加一分，显式传入优先 | 「没有显式打分时按内容信号估计」 |
| 哈希去重 + 近似合并 | Mem0 / LivingMemory | SHA-1 精确去重（5 分钟窗口）+ Jaccard ≥ 0.82 合并到旧记忆并强化 | 「高度相似的记忆合并为一条并强化」 |
| 空闲时整理记忆 | Letta sleep-time | 状态切入 `sleep` 时异步触发 `dailyReview()`，不阻塞对话；`reviewOnSleep` 可关 | 决策循环代码路径 |
| 同类行为防重复 | dsh-proactive 的 tombstone 思路 | `minActionGapMs`，同类动作间隔不足则跳过本次唤醒且不消耗预算 | 决策循环代码路径 |

## 六、暂不吸收，以及为什么

| 能力 | 不做的原因 |
|------|-----------|
| 向量检索 / Embedding | 本机部署成本高，且默认路径必须零依赖；接口已留，未来可作为可选增强 |
| 图记忆（实体/关系/有效期） | 构图与维护成本高，个人陪伴场景收益不确定；先把三信号与审计做扎实 |
| Agent 主动召回工具（recall/memorize） | 需要 DSH 工具注册 API 的稳定契约；当前用运行时上下文注入已覆盖大部分场景，等 05 平台层稳定后再评估 |
| 让模型自改 core memory | 与“人格锚定不可自改”冲突；我们选择面板受控写入 |
| sleep-time 后台 Agent 做 LLM 整理 | 需要模型调用通道；当前 `summarizer` 已留注入位，先跑确定性规则 |
