# 22 · 形象资源包分发与下载设计（2026-11-13）

> 21 号稿解决“形象库长什么样、怎么用”。本稿只解决一件事：
> **13 张 2848×1600 原图不进 Git，放在 GitHub Release；网页整套下载到本机。**
> 目标是不让第一次 clone 多下 74MB，同时下载时页面不卡、不占大内存。

## 一、拍板结论

| 项 | 结论 |
|----|------|
| 托管位置 | 同仓库 `swluo777/dsh-fish-dandan` 的 GitHub Release |
| Release tag | `character-dandan-v1` |
| Git 保留 | 13 张 640×360 WebP 缩略图（约 0.51MB）、`manifest.json`、`README.md`、`LICENSE.md`、`assets/character-packs.json` |
| Git 不保留 | 13 张 2848×1600 PNG 原图（合计 77,393,766 bytes） |
| 下载方式 | 13 个 PNG 单文件下载，不打 zip |
| 下载并发 | 4 个 `worker_threads` worker，流式写盘 |
| 安装位置 | `data/characters/packs/dandan-initial/`（被 `.gitignore` 忽略） |
| 前端 | 先显示缩略图；资源卡“下载全部 13 张原图”，后台任务 + 轮询进度 |

## 二、为什么是 Release，不是 LFS / Pages

- GitHub 普通仓库单文件超过 100MiB 会被拒；官方建议大文件走 Release。
- Release 单个附件 <2GiB、单 release 最多 1000 个附件；官方不限制 release 总大小和下载带宽。
- Release 附件挂在 tag 上，不是 Git 对象；`git clone` 不会下载。
- Git LFS 在 clone/pull 时仍会通过指针拉真实文件，且依赖 git-lfs 与配额，不适合“可选下载”。
- GitHub Pages 是 1GB 站点 / 100GB 月带宽软限制，适合网页，不适合当二进制分发。

## 三、仓库里保留什么

```text
assets/
  character-packs.json          # 资源包清单：版本、Release tag、文件大小、SHA-256
  character/dandan/
    manifest.json               # 13 张图的元数据
    README.md
    LICENSE.md
    01-child-cream-sailor-thumb.webp
    ...
    13-teen-initial-maid-v8-thumb.webp
```

`manifest.json` 的 `images[]` 仍是唯一图片索引；每张图带 `file`（Release 里的文件名）、`thumbFile`、`bytes`、`sha256`、`origin: "release"`。

`assets/character-packs.json` 是下载器的唯一输入：

```json
{
  "packs": [{
    "id": "dandan-initial",
    "version": "1.0.0",
    "releaseTag": "character-dandan-v1",
    "baseUrl": "https://github.com/swluo777/dsh-fish-dandan/releases/download/character-dandan-v1",
    "totalBytes": 77393766,
    "fileCount": 13,
    "files": [
      { "path": "01-child-cream-sailor.png", "bytes": 6132284, "sha256": "..." }
    ]
  }]
}
```

## 四、下载器

### 4.1 任务模型

```text
POST /characters/packs/install { packId }
  -> { jobId }                 # 立即返回，不在 HTTP 请求里等 74MB
GET  /characters/packs/status?id=jobId
  -> { status, filesDone, filesTotal, bytesDone, bytesTotal, speedBps, error }
```

任务状态：`running` / `done` / `failed`。页面每 700ms 用 `setTimeout` 轮询，避免 `setInterval` 重叠请求。

### 4.2 并发

- 4 个 `worker_threads` worker，不是 13 个并发，避免把带宽和 GitHub 连接打满。
- 每个 worker 一次处理一个文件：
  1. `fetch` 或代理 `curl` 下载；
  2. 流式写到 staging 临时文件（正式目录不可见）；
  3. 边写边算 SHA-256；
  4. 回传字节进度。
- 主线程只维护任务状态和聚合进度，不做大文件读取/哈希。
- 单文件失败重试 2 次；只重试该文件，不重下整包。

### 4.3 校验与原子安装

1. 下载到 `data/characters/packs/.staging/dandan-initial-<timestamp>/`；
2. 每个文件校验 `bytes` 和 `sha256`；
3. 全部通过后写 `install.json`；
4. 旧版本先改名为备份，staging 原子重命名到正式目录；失败则恢复备份；
5. 成功后清理备份与临时目录。

Windows 在杀毒软件、浏览器或系统索引占用刚下载的图片时，会返回 `EPERM` / `EBUSY` / `EACCES` / `ENOTEMPTY`。删除和改名统一走 `src/utils/fs-retry.js` 的退避重试；改旧目录名仍失败时，先清理旧目录再放入 staging。多轮重试仍失败时返回 `PACK_LOCKED`，页面提示“先关掉正在看的原图，或等几秒再试”，不再直接暴露系统错误码。

页面在任何时候都不会看到半套图。

### 4.4 代理

复用 `src/stickers/net.js` 的代理探测结果；worker 内优先 `fetch`，探测到系统代理时改用异步 `curl` 落盘。**不复用 `httpGet` 的 `arrayBuffer()` 整块读逻辑**，避免大文件占内存。

## 五、API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/characters` | 合并 manifest + 本机安装状态；返回 items、pack、主形象 |
| GET | `/characters/thumb?id=` | 缩略图，永远从仓库 `assets` 读 |
| GET | `/characters/file?id=` | 原图，只有安装完成才返回；否则 409 `PACK_NOT_INSTALLED` |
| GET | `/characters/packs` | 可用包、已安装版本、活动任务 |
| POST | `/characters/packs/install` | 启动下载任务，返回 `jobId` |
| GET | `/characters/packs/status?id=` | 查询任务进度 |
| POST | `/characters/packs/remove` | 删除本机原图；任务运行中返回 `PACK_BUSY`，文件被占用返回 `PACK_LOCKED` |
| POST | `/characters/primary` | 设主形象，写 `data/state/character.json` |

路径安全：

- 只接受 manifest 里存在的 `id`；
- 缩略图路径 `path.resolve(assets/character/dandan, thumbFile)` 必须在目录内；
- 原图路径 `path.resolve(packs/dandan-initial, file)` 必须在目录内；
- 不接受客户端传文件名、URL 或绝对路径；
- 下载 URL 只从 `character-packs.json` 生成，域名必须是 `github.com` / `objects.githubusercontent.com`。

## 六、页面

- 左侧导航：`形象`；页面标题：`形象库`；放在“人格”后、“记忆”前。
- 页面按渐进式披露组织，首屏只保留必要信息：
  - 大预览 + 当前形象的年龄段 / 造型 / 版本；主形象用纯文字状态，不做成不可点的按钮；
  - 点主预览或网格缩略图打开大图查看；原图已下载时看原图，否则看缩略图并提示先下载；
  - 只有非主形象才显示“设为主形象”；
  - 文件、标签、单张原图下载、复制文件名直接展示，不再收进“形象详情”折叠区；
  - 资源包只留一个入口：未下载时显示“下载全部 13 张原图”；下载中显示文件数、字节数和速度；完成后显示“原图已下载”；
  - 已下载后，重新下载和删除本机原图直接放在资源卡里，不再收进“管理本地原图”折叠区。
- 筛选拆成两行：年龄一行（全部/幼年/少女/成年），造型单独一行（全部/女仆/水手/星庭/极光）。
- 网格：13 张缩略图；卡片角标只保留必要的 `初始` / `主形象`，原图状态用一个小勾提示，不额外放按钮。
- 不展示来源、许可、资源包大小、本机路径、是否进 Git 这类内部备注；这些只留在清单和文档里。
- 下载按钮只触发后台任务，页面可以切走；回来继续看进度。

## 七、许可

- 13 张原图按 **CC BY-NC-SA 4.0** 分发，不是 MIT。
- Release 页面必须带署名、非商业、相同方式共享说明。
- 公开 Release 属于再分发；商用、带货、打包分发前需取得原作者许可或换原创设定。

## 八、验收

1. `git clone` 后 `assets/character/dandan/` 只有缩略图，没有 13 张 PNG；
2. 首次进形象页，13 张缩略图可见，页面不请求 74MB；
3. 点下载后 `POST` 立即返回，页面不转圈等待；
4. 下载中显示 4 个 worker 的聚合进度，页面可滚动、可切标签；
5. 断网/单文件 404 时只重试该文件，失败后不出现半套图；
6. SHA-256 不匹配时任务失败并清理 staging；
7. 下载完成后 `/characters/file?id=` 可看原图，`/characters` 标记原图已下载；
8. `git status` 不出现 13 张 PNG。
