# 01 · 人格模块（persona）实施任务单

> 结构：同类插件怎么实施 → 优缺点 → 取舍 → 我们的设计 → 任务单。执行 AI 先读 `AGENTS.md` 与 `00`。

## 一、同类插件的人格实施机制（已核实）

| 插件 | 怎么实施人格 |
|------|--------------|
| 官方 dsh-system-prompt | 部署层一段文本，分**全局 / 会话两层**；每步重新组装，agent 级 persona 覆盖全局 |
| dsh-soul-md | 设置页输入人设卡，**插件自动管理文件**；提供 soul_read/soul_update，AI 可自行演化，可按工作区/会话切换 |
| dsh-agent-md | 用 Markdown 定义 agent（含 system prompt + model），@mention 调度子 agent |
| dsh-persona-dafeiyu | 人格库：内置 3 套 + 文件导入 + 粘贴文本，profile 级或会话级注入 |
| AstrBot 人格 | 人格是系统提示词配置项，**在管理面板可视化配置、不改代码**；情绪/亲密度由独立插件叠加 |
| AGENTS.md | 持久 baseline user message（有 64KiB 预算），作为约定与固定指令注入 |

## 二、各方案优缺点

- **官方分层 Persona**：优点是稳定指令与易变事实分离、每步可重放、可覆盖；缺点是纯静态文本，无成长、无结构化校验。
- **dsh-soul-md**：优点是有界面、文件自管理、有自演化雏形；缺点是让 AI 直接改人格缺少锚定，易人格漂移，个人维护更新不稳。
- **dsh-agent-md**：优点是多角色隔离清晰；缺点是面向子 agent 调度，不是主陪伴人格。
- **AstrBot 人格**：优点是面板化、零代码、插件生态多；缺点是人格与记忆割裂，成长靠零散插件拼接，无统一内核。

## 三、取舍（取其精华、去其糟粕）

- **取**：官方的全局/会话分层与每步组装；soul-md 的文件自管理与面板化；AstrBot 的可视化编辑；结构化字段与校验。
- **去**：纯文本不可控；让 AI 无锚定自改人格导致漂移；人格与记忆混写；多插件拼接造成的不一致。
- **我们的原则**：核心人格锚定（结构化、可校验、不被模型自行篡改），成长特质单独成层（由记忆模块受控沉淀），二者运行时合并注入。

## 四、我们的设计

### 4.1 人格数据结构（Persona Schema）

默认模板 `persona/default-persona.json`（入库，无密钥/敏感信息）：

| 分组 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 身份 | name | string | 名字 |
| 身份 | species | string | 物种/形象，如“蓝色大肥鱼” |
| 身份 | age | string | 年龄（成人角色必须显式写“成年”，避免被当未成年） |
| 身份 | appearance | string | 外貌细节：头发、耳朵、穿着、尾巴等一眼能认出的特征 |
| 身份 | identitySummary | string | 一句话身份背景 |
| 性格 | traits | object | 五维各 1–10：openness、extraversion、agreeableness、stability、conscientiousness |
| 性格 | tags | string[] | 性格标签，2–4 个词最有用（傲娇、贪吃、科技宅…） |
| 性格 | personalityText | string | 性格文字描述 |
| 说话风格 | tone | string | 整体语气 |
| 说话风格 | selfReference | string | 自称 |
| 说话风格 | ownerAddress | string | 对主人称呼（占位，负责人填） |
| 说话风格 | catchphrases | string[] | 口头禅（最多 12 条，每条 ≤80 字） |
| 说话风格 | styleNotes | string | 语言习惯补充 |
| 偏好 | likes / dislikes | string[] | 喜欢 / 讨厌 |
| 日常 | scenes | string[] | 什么情况下会怎么反应；一行一条，最多 8 条，每条 ≤160 字 |
| 边界 | boundaries | string[] | 硬边界：拒绝就是拒绝、不伤人、不冒充真人；与全局安全规则冲突时以全局为准 |
| 背景 | backstory | string | 背景故事 |
| 安全 | safetyRulesRef | string | 指向独立安全规则，不混写 |

### 4.2 存储

- 入库模板：`persona/default-persona.json`；
- 运行时：`data/persona/core-persona.json`（gitignore），首次运行无则从模板复制；
- 成长特质：仅定义读取接口 `getEvolvedTraits()`，本单先返回 `{}`，由记忆/决策模块实现。

### 4.3 接口契约（`src/persona/index.js` 导出）

- `loadPersona()`：读取并校验，非法则回退默认模板；
- `buildPersonaSection(persona, evolvedTraits)`：返回稳定人格锚点文本（不含易变事实）；
- `injectIntoPreStep(ctx)`：在 `agent/pre-step` 注入，保留 `await next()` 透传，可附加消息不得短路。

注入优先级：安全规则 → 核心人格锚点 → 成长特质（预留）。

## 五、验收标准

1. 全部 `node --check` 通过；
2. 运行时文件缺失/损坏自动回退，不崩溃；
3. 日志可确认每步注入人格段，多轮、多平台人设一致；
4. 代码与模板无密钥、无明文外泄路径；
5. 未注入额外内容时与原透传行为一致，不阻断 Agent。

## 六、禁止事项

- 禁止人格与情景记忆混存；禁止在本模块实现记忆衰减或状态机；
- 禁止模型在运行时直接改写核心人格文件（写入只能经面板/受控接口）；
- 禁止降低安全规则优先级；禁止自动提交；禁止凭未核实字段编码。
