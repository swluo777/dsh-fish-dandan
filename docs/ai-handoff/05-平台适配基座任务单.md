# 05 · 平台适配总览与通信基座（platform-core）实施任务单

> 结构：同类机制 → 优缺点 → 取舍 → 我们的设计 → 任务单。本单只做“基座与契约”，不实现具体平台（QQ/抖音/B站分别在 06/07/08）。前置：`00`–`04`。

## 一、同类机制（已核实）

| 方案 | 做法 |
|------|------|
| dsh-onebot-hub | 设置页配置上游：类型（OneBot/QQ 官方）、连接（反向 WS/正向 WS）、地址；推荐实现端反连 hub，换 IP 不影响 |
| dsh-onebot | OneBot v11 适配器，支持 HTTP、正向/反向 WS；forward-ws（默认）、reverse-ws；用 access_token 鉴权 |
| NoneBot 适配器模型 | 适配器由 **Adapter、Bot、Event、Message** 四部分组成 |
| zhin 消息流 | 归一化 IncomingMessage：conversation（endpoint/kind/id/threadId）、message（native id）、content、segments |
| 通用 Chat Adapter | 跨平台只映射确定语义，平台私有内容保留在 `raw`，不把私有概念伪装成标准字段 |

## 二、优缺点与取舍

- **取**：标准适配器四要素、统一归一化消息结构、确定语义才映射 + raw 保留、反向 WS 反连、access_token 鉴权、能力声明。
- **去**：各平台各写一套处理逻辑、私有字段污染内核、凭证写死在代码里。
- **原则**：内核只认“归一化消息 + 统一身份”，平台差异全部收敛在适配器内，新增平台不改内核。

## 三、我们的设计

### 3.1 归一化消息模型（NormalizedMessage）

| 字段 | 内容 |
|------|------|
| conversation | platform、kind（私聊/群/评论/私信）、externalId、threadId |
| sender | platformUserId、unifiedPersonId（身份归一后的内部 ID） |
| content | 纯文本内容 |
| segments | 图片/表情/链接等结构化消息段，统一类型 |
| nativeMessageId | 平台原始消息 ID（用于回复/撤回） |
| raw | 原始事件完整保留，不丢平台私有信息 |

### 3.2 平台适配器接口（PlatformAdapter，06/07/08 实现）

- `connect()` / `disconnect()`：建立与维护连接、断线重连；
- `normalize(event)`：平台事件 → NormalizedMessage；
- `send(conv, message)`：内核回复 → 平台格式并发送；
- `capabilities()`：声明该平台支持的动作（文本/图片/评论/私信/群聊/加好友等）。

### 3.3 身份归一（IdentityRegistry）

- 维护 `platform + platformUserId ↔ unifiedPersonId` 映射；
- 同一真实用户跨平台识别为同一人；同一条鱼自身在各平台的账号也登记映射；
- 映射持久化到 `data/identity/`，未识别身份先建临时档，确认后合并，不重复建档。

### 3.4 消息路由（MessageRouter）

链路：平台事件 → 适配器归一化 → 身份识别 → 内核（人格/记忆/状态机）→ 回复决策 → 对应平台发送。
- 对内与对外统一走此路由，便于审计与限流；
- 平台凭证（access_token、登录态、Cookie）只走环境变量/DSH 凭证层，不进代码与日志。

### 3.5 拟人化与安全

- 发送随机延迟、频率上限、对外动作（评论/加好友/公开内容）默认人工确认；
- 复用 02 的安全闸门，平台输入同样做注入检测。

## 四、接口契约（`src/platform/index.js` 导出）

- `defineAdapter(impl)`：注册平台适配器；
- `getAdapter(platform)` / `listCapabilities()`；
- `routeIncoming(event)` / `routeOutgoing(conv, msg)`；
- `resolveIdentity(platform, platformUserId)` / `mergeIdentity(from, to)`；
- `attach(ctx)`：挂载路由与连接生命周期，`ctx.effect()` 保证卸载清理。

## 五、验收标准

1. `node --check` 通过；可用一个 mock 适配器端到端跑通“进入→归一→内核→回复→发送”；
2. 归一化字段与 raw 完整，平台私有信息不丢失、不污染内核；
3. 身份映射可识别跨平台同一人，重复事件不重复建档；
4. 断线重连、限流、随机延迟、人工确认生效；凭证不入库、不进日志；
5. 新增一个平台只需实现适配器接口，内核与其他模块零改动；
6. 不自动提交，改动交负责人审查。

## 六、禁止事项

- 禁止在本单实现具体平台业务逻辑；禁止内核直接处理平台私有格式；
- 禁止硬编码凭证/绝对路径；禁止跳过安全闸门与人工确认；
- 禁止自动提交与未核实字段编码，开发当天重读官方文档确认接口。
