# 02 · 记忆模块（memory）实施任务单

> 结构：同类插件怎么实施 → 优缺点 → 取舍 → 我们的设计 → 任务单。前置：`AGENTS.md`、`00`、`01`。

## 一、同类插件的记忆实施机制（已核实）

| 插件 | 怎么实施记忆 |
|------|--------------|
| LivingMemory（AstrBot） | 达轮次自动总结为长期记忆；**双路四模式检索**（文档+图谱，关键词+向量）；记忆原子带 TTL、衰减、访问强化、自动清理 |
| bluezeamer memoryv1.3 | 零依赖纯标准库，**按人建档、纯 Markdown**，可直接打开改 |
| Cairn（chenhw7） | 记忆是**流水线**：信号感知→LLM 抽取→安全闸门→KV+审计→BM25 检索→上下文注入 |
| FishMem | **canonical 记录 + 可重建投影**，本地 embedding + SQLite，投影故障不影响原始记录 |
| zheexinn/dsh-memory | 默认**字符 n-gram 索引（CJK bigram）零外部依赖**，嵌入层可插拔替换 |
| dsh-ai-memory | SQLite，记忆分 tier（working/episodic/profile），含 last_accessed、access_count、pinned |
| daoing-memory | **append-only diary 基底** + 单 SQLite，所有变更可审计 |

## 二、各方案优缺点

- **LivingMemory**：检索强、生命周期完整；缺点是依赖独立 Embedding 服务，部署重。
- **bluezeamer**：零依赖、透明可读、按人建档；缺点是 Markdown 不适合大规模语义检索与并发。
- **Cairn / FishMem**：流水线与安全闸门清晰、canonical 不可变、投影可重建，可信；缺点是结构偏复杂。
- **zheexinn**：不强制 embedding 服务即可语义检索，工程友好；缺点是 n-gram 召回质量不如真向量。
- **dsh-ai-memory / daoing**：分层、可审计、字段规范；缺点是各自封装，跨平台不互通。

## 三、取舍

- **取**：tier 分层、SQLite 单文件、append-only 审计、canonical 不可变 + 投影可重建、TTL + 访问强化、安全闸门置于持久化前、按人/平台建档、嵌入层可插拔（默认不强依赖外部服务）。
- **去**：黑盒 pkl；只适合小规模的纯 Markdown 检索；把“能否运行”绑死在外部 Embedding 服务上。
- **原则**：原始事实不可删改（只追加），派生层可重建；记忆写入前必须过安全闸门。

## 四、我们的设计

### 4.1 三层记忆模型

| 层 | 内容 | 衰减 | 字段要点 |
|----|------|------|----------|
| 永久锚定 anchor | 核心事实、关键关系、被 pin 的约定 | 不衰减 | pinned=true，可手动归档 |
| 长期特质 trait | 兴趣、技能、偏好、关系亲密度 | 慢变化 | 由每日复盘从情景层沉淀，反馈给人格 `getEvolvedTraits()` |
| 情景事件 episodic | 具体经历、对话摘要、平台事件 | 时间衰减 | importance(1–10)、created_at、last_accessed、access_count、来源平台、人物标识 |

### 4.2 存储

- 主库：`data/memory/memory.db`（SQLite，gitignore），表：`memories`（含 tier、importance、计数、时间、pinned）、`audit_log`（append-only）；
- 检索投影：默认 BM25/字符 n-gram 索引；向量嵌入通过可插拔接口 `memoryEmbedding` 提供，未配置时降级 n-gram，不阻塞启动；
- 原始记录只追加，更新/删除走审计记录，投影可从 canonical 重建。

### 4.3 接口契约（`src/memory/index.js` 导出）

- `recordEvent(raw, source)`：经安全闸门后写入情景层；
- `recall(query, { tier, limit, platform, person })`：检索并在命中时做访问强化；
- `dailyReview()`：用 LLM 从近期情景抽取特质写入 trait 层，产出供人格模块读取；
- `pinAnchor(id)` / `getEvolvedTraits()`；
- `attachToPreStep(ctx)`：在 `agent/pre-step` 按需注入相关记忆，不全部塞入，保留 `await next()`。

## 五、验收标准

1. `node --check` 通过；数据库可打开、表结构与字段齐全；
2. 未配置 Embedding 时系统用 n-gram 正常运行，配置后自动启用向量检索；
3. 衰减、访问强化、pin、TTL 清理可被单测/日志验证；
4. 每日复盘能把情景沉淀为特质，并被人格模块读取；
5. 所有写入有审计记录，安全闸门能拦截注入/敏感内容；
6. 无密钥入库，不自动提交。

## 六、禁止事项

- 禁止物理删除/覆盖原始记忆（只追加 + 审计）；
- 禁止跳过安全闸门直接持久化；禁止把全部记忆无差别塞进提示词；
- 禁止让记忆模块直接改核心人格文件；禁止自动提交与未核实字段编码。
