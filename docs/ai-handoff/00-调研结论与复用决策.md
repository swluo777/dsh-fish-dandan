# 00 · 调研结论与复用决策（给执行 AI 的背景与边界）

本文件说明同类项目怎么做、哪里好哪里不好，以及本项目每个模块的复用/自研决策。执行 AI 必须先读本文件与 `AGENTS.md`，再按具体任务单开发。

## 一、同类方案对比（基于公开文档与仓库核实）

| 方案 | 做法 | 优点 | 不足 |
|------|------|------|------|
| 官方 dsh-system-prompt | 全局/会话两层 Persona 文本，每个模型步骤重新组装 | 稳定指令与易变事实分离，架构干净，可重放 | 仅静态文本，无成长、无记忆沉淀 |
| dsh-fish-memory | 情景记忆 + 艾宾浩斯时间衰减 + 语义检索 | 能“遗忘”，会话内可召回 | 只有情景记忆，无特质演化，跨平台不互通 |
| dsh-soul-md | 人格+记忆一体，设置页管理文件，soul/memory 读写 | 有界面、有自我演化雏形 | 演化逻辑简单，个人维护，更新不稳定 |
| dsh-agent-md | Markdown 人格卡，@mention 调度子 agent | 多角色、隔离清晰 | 偏向子 agent 调度，非主陪伴人格 |
| AstrBot | 消息分发 + 插件容器 | 插件多、开箱即用、多平台 | 无深度 Agent 思考，成长有天花板 |

## 二、关键结论

1. 现有生态把“人格、记忆、决策”拆成零散单点，**没有一个项目形成“经历→记忆→特质→行为”的成长闭环**，这正是本项目的差异化空间；
2. 宿主级思考能力（工具调用、规划、反思）由 DSH 官方团队迭代，个人不重写，只通过插件 API 接入；
3. 数据结构与存储必须先于界面设计，避免后期返工。

## 三、复用 / 自研决策（逐模块）

| 模块 | 决策 | 理由与合规要求 |
|------|------|----------------|
| DSH 引擎 | 作为运行时宿主，不复制 | 仅依赖其公开插件 API，不修改宿主源码 |
| QQ 接入（NapCat/SnowLuma） | 外部独立进程，OneBot 协议对接 | 不抄协议代码，避免逆向与封号风险 |
| 浏览器自动化（抖音/B站） | 以 Playwright 为依赖，自行封装 | 参考现有插件思路但不整体复制，加拟人化随机控制 |
| 人格 persona | **自研** | 核心差异，只参考分层思想，不复制代码 |
| 记忆 memory | **自研** | 三层记忆+衰减+复盘，算法参考艾宾浩斯，代码独立 |
| 状态机 decision | **自研** | 五状态驱动，替代生硬定时任务 |
| TTS / 绘画 | 调用 API 或独立插件 | 不抄实现，仅封装调用 |
| 通用第三方库 | 优先 npm 声明依赖 | 仅选 MIT/Apache/BSD 等宽松协议，登记 THIRD_PARTY_NOTICES |

## 四、复用总原则

1. **优先声明依赖，其次构建打包，最后才物理复制**；目标“一键可用”通过锁定依赖 + 打包实现，不靠抄代码；
2. 仅当需要深度修改且依赖不可替代时，才放入 `third_party/`，并保留全部许可声明；
3. 强传染协议（GPL/AGPL）组件与本项目 MIT 分发组合前必须评估，不兼容则换替代或自研；
4. 任何引入都登记到 `docs/legal/THIRD_PARTY_NOTICES.md`，禁止漏项。
