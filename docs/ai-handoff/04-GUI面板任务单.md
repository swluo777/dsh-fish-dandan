# 04 · GUI 设置面板（browser 半）实施任务单

> 最终目标：插件出现在 DSH 插件列表，可点击进入，手动完成人格、记忆、状态机的查看与设置。前置：`01`–`03` 已实现并暴露读写接口。

## 一、同类插件的前端实施机制（已核实）

| 方案 | 怎么实施界面 |
|------|--------------|
| dsh-plugin-template | `src/client/config-card.tsx` **手写表单**，每个可编辑字段一行（label/hint/FIELDS/buildOps/draftValue） |
| dsh-settings-ui | 统一设置页 UI kit + 浮动面板，提供 `ctx.settingsUi` 与 `--dsw-*` 语义 token，保持主题一致 |
| ui-surfaces 规范 | config-card 插槽 `settings.plugin.item`，位于 **设置→插件→配置**，**staged 表单（草稿→保存）**，需 host 半提供 config 形状 |
| dsh-kit-settings | browser 半，在设置里加可折叠“插件配置”卡片 |
| slots 机制 | 用 `ctx.slots.register` / `ctx.slots.inject` 注册到运行时声明的插槽 |

## 二、优缺点与取舍

- **取**：`settings.plugin.item` 标准插槽、staged 草稿表单、用语义 token/UI kit 对齐官方主题、host 半集中提供数据接口。
- **去**：自定义悬浮入口破坏官方布局、表单直接写盘无草稿、前后端字段各写一套导致不一致。
- **原则**：面板字段与 `01` 的 Persona Schema、`02/03` 的数据结构**一一对应、单一数据源**，界面只是读写外壳。

## 三、技术结构

- 浏览器半独立 bundle：`src/client/`，`package.json` 声明 `dsh.client` 与 `./client` 导出；
- 入口用 `ctx.slots.register('settings.plugin.item', ...)` 注册配置卡片；
- 前端通过 host 半暴露的受控 API 读写数据（不直接访问文件系统）；
- 优先使用 `dsh-settings-ui` 组件与语义 token，适配浅色/深色主题与窄屏。

## 四、面板分区（对应三个模块）

1. **人格设置**：按 `01` 字段表渲染表单（身份、性格五维滑块、说话风格、偏好、背景），保存前为草稿，保存调用受控写入；核心人格不允许模型运行时自改，只能在此或受控接口修改。
2. **记忆管理**：搜索/浏览三层记忆，查看来源与时间，pin 锚定、查看审计日志、触发手动清理；展示衰减与访问计数。
3. **状态机**：实时显示当前状态与五个内部变量，展示决策依据；提供手动 `nudge` 下发临时计划；配置静默时段、每日预算、抖动等调度参数。
4. **安全**：查看安全规则与注入/审批记录，高风险动作的确认入口。

## 五、接口契约（host 半需为前端提供）

- `getState()` / `updatePersona(draft)` / `searchMemory(query)` / `pinMemory(id)` / `nudgeDecision(action)` / `getAuditLog()`；
- 所有写接口复用 `01`–`03` 的校验与安全闸门，前端不绕过；
- 通信走 DSH 官方网关，不自行开放网络端口。

## 六、验收标准

1. 插件在 DSH 插件列表可见，点击进入设置卡片，无报错；
2. 人格表单可编辑、可取消、保存后持久化并在对话中生效，刷新不丢草稿状态规则符合预期；
3. 记忆可搜索/ pin / 清理，状态机变量与 nudge 实时生效；
4. 浅色/深色主题与窄屏显示正常，字段与后端 schema 完全一致，无僵尸按钮；
5. 任何写入都经过校验与安全闸门，无密钥出现在前端或日志；
6. 不自动提交，改动交负责人审查。

## 七、禁止事项

- 禁止前端直连文件系统/自建网络端口/硬编码密钥；
- 禁止面板字段与后端 schema 出现第二套定义；禁止跳过校验直接写库；
- 禁止自动提交与未核实插槽/API 编码，开发当天重读官方文档确认字段。
