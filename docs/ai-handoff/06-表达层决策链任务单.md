# 06 · 表达层决策链任务单

> 目标：把「文字 / 抖音面板表情 / 自定义表情包」从四条链路各自判断，收敛成一套共用顺序；像人一样先判断这轮要不要说清楚，再决定用不用表情；表情匹配不上就退回上一层，不硬发。

## 一、现状审计

### 1. 已有的三条策略

- `src/voice/expression.js`
  - `EXPRESSION_LEVELS`：`restrained / natural / playful`，分别有 `textEmoji / panelEmoji / sticker` 三个概率。
  - `isSeriousContext`、`isStickerEligible`、`isStickerOnlyIntent`、`inferIntent`、`hasEmoji`。
  - 只做判断，不发消息。
- `src/platform/douyin/dm-auto.js`
  - 被动私信：先让模型生成文字，再按概率尝试用自定义表情包替换文字；没有面板表情回退。
  - 只从「最后一条对方文字」找语义；纯图片/表情包来信不会触发表情包选择。
  - 先用列表预览 `item.last`，线程里的最新来信反而靠后。
  - `isStickerOnlyIntent` 定义了但没用；没有判断「模型草稿是不是内容型回复」，只要语义分够高就可能把一段有信息量的回复替换成图。
- `src/platform/douyin/duty-server.mjs`
  - 评论/回复：模型通过 `douyin_say` 显式传 `emoji` / `stickerId` / `stickerQuery`；服务端只做互斥和存在性校验，没有统一的「内容型 vs 社交型」判断。
  - `commentStickerQuery` 把「自己的评论 + 视频文案 + 前 5 条评论」拼在一起，评论区噪音会稀释语义。
  - `stickerQuery` 匹配不到直接报错，没有「先退面板表情、再退文字」的中间层。
  - 主动私信：`douyin_dm_send` 只发文字，`douyin_send_sticker` 单独发图，两条链路各自判断，频控也各自消耗。

### 2. 三个明显缺口

1. 没有「这轮是内容型还是社交型」的统一前置判断。
2. 没有「自定义表情包匹配失败 → 面板表情 → 文字」的中间回退层。
3. 没有区分平台能力：评论/回复是「文字必填，图是附加层」，私信是「文字或图二选一」，主动私信是「文字为主，图可附加」。

## 二、真人发消息的顺序

### 1. 先判断这轮要不要说清楚

**内容型（必须文字）**：

- 对方在问一件事：怎么、为什么、多少、哪里、什么时候、能不能、帮我、在哪、多少钱、怎么办、几点、多久等。
- 严肃/冲突/隐私：分手、吵架、生气、难过、崩溃、去世、生病、住院、借钱、被骗、身份证、银行卡、密码、验证码、地址、电话等。
- 需要解释、安慰、给方案、确认安排、带信息量。
- 对方发了需要理解的图片/视频，且回复里要说出具体内容。

内容型只用文字，最多带一个文字 emoji；不拿表情包或面板表情顶答案。

**社交型（可以考虑表情）**：

- 在吗、在不在、收到、好的、谢谢、哈哈、笑死、晚安、早安、抱抱、辛苦了、同意、可以、没问题、来了、稍等、加油、没事、不客气、真的假的、离谱、绝了等。
- 回复本身也是短社交反应，不是提问、不是解释、不是给信息。
- 不严肃、不冲突、不涉及隐私。

**不确定**：按内容型走文字。宁可少一个表情，不要图不达意。

### 2. 平台能力矩阵

| 场景 | 文字 | 抖音面板表情 | 自定义表情包 | 图文同一条 |
|---|---|---|---|---|
| 评论 | 必须 | 可，且与图互斥 | 可，文字 + 图 | 是 |
| 回评论 | 必须 | 当前发送层未接 | 可，文字 + 图 | 是 |
| 被动私信 | 文字或图二选一 | 当前 Web 私信未接 | 可单独发 | 否（当前） |
| 主动私信 | 文字为主 | 未接 | 已支持文字 + 图 | 是（只算一次频控） |

### 3. 选择顺序

```
内容型 ──> 文字（可带文字 emoji）
社交型
  ├─ 自定义表情包可用、且短社交回复适合用图
  │    ├─ 语义检索有高分且不歧义的 top1 ──> 自定义表情包
  │    └─ 没有 / 分不够 / 太歧义 / 最近刚发过 ──> 下一层
  ├─ 平台支持面板表情，且这句话有明确情绪 ──> 面板表情
  └─ 都不行 ──> 文字（可带文字 emoji）
```

**回退顺序固定为：自定义表情包 → 面板表情 → 文字。**
不是「随机抽一张图」，也不是「面板表情永远点第一个」。

### 4. 面板表情怎么选

- 只按「我们准备发出去的这句话」的情绪选，不按对方最后一句话的情绪选。
- 明确映射：
  - 笑/哈哈/笑死 → 笑哭
  - 谢谢/多谢 → 抱拳
  - 好的/收到/同意 → 点赞
  - 抱抱/安慰/心疼 → 爱心
  - 无语/离谱/就这 → 无语
  - 惊讶/真的假的 → 惊讶
  - 委屈/难过 → 委屈
  - 在吗/你好/再见 → 挥手
  - 生气/烦 → 无语（没有合适表情就不发）
- 没有明确情绪、映射不到、面板里找不到对应标签 → 不带面板表情，直接文字。
- 面板表情不是默认项；不传就不带，服务端不点第一个。

### 5. 自定义表情包的匹配门槛

- 查询词优先用「我们准备回的那句话」，再加对方最后一句话/视频文案；**不再把评论区前几条拼进来**。
- 只从有 `caption` 的图里选；`tagOnly` 旧图只在「一张图就能完成短社交」时兜底，且门槛更高。
- 硬门槛：
  - 有 caption：`score >= 0.40`
  - tagOnly：`score >= 0.36`，且只允许短社交
  - top1 与 top2 分差 `< 0.03` 且 top1 没有命中目标 intent → 视为歧义，退回下一层
  - `confidence < 0.45` 时，`score` 要再高 0.04
  - 文件必须存在
- 最近刚发过的同一张图（同一会话 2 小时内）跳过，优先下一张；没有下一张就退回面板表情/文字。
- 概率门只作用在「已经通过全部硬门槛」之后；概率不过就退回下一层，不硬发。

### 6. 频控

- 被动私信：保留现有防刷（60 秒 10 条以上暂停 5 分钟）；不按「刚回过」做固定冷却。
- 评论/回复：模型决定，不按每条强制概率；但要遵守「一条最多一个表达层、不要每条都带、同一张图不连着发」。
- 主动私信：保留 10 分钟 / 每小时 2 条硬频控；文字 + 图算一次，不再出现「文字发完、图被频控挡住」。

## 三、代码改动清单

### 1. `src/voice/expression.js`

新增/调整：

- `isInformationQuestion(text)`：区分「真在问信息」和「在吗？」这种社交问句。
- `isStickerEligible` 改为排除信息型提问，不再一律排除问号。
- `isStickerOnlyIntent` 扩一点短社交词，但保持「一张图能完成回复」的原意。
- `isStickerReplyEligible({ incoming, reply, incomingKind })`：内容型/严肃/长回复/带信息词一律 false。
- `pickStickerCandidate(hits, { intent, allowTagOnly, minScore, minGap })`：统一高分、分差、confidence、tagOnly 门槛。
- `panelEmojiForIntent(intent)` / `panelEmojiForText(text)`：意图到面板表情名称的映射；没有明确情绪返回空。
- `buildStickerQuery({ replyText, incomingText, extra, max })`：回复文本优先，上下文补充，不拼评论区噪音。
- `inferIntent` 补「加班/好累/忙死」到 comfort，补「裁员/失业」到严肃上下文。

### 2. `src/platform/douyin/dm-auto.js`

- `chooseSticker` 改为基于线程最新来信 + 模型草稿；不再优先用列表预览。
- 先过 `isStickerReplyEligible`，再查语义；查询词用「最新来信 + 草稿」。
- 用 `pickStickerCandidate` 统一门槛；`isStickerOnlyIntent` 真正参与判断。
- 纯图片/表情包来信允许走「草稿是短社交反应」的图路径。
- 记录每个会话最近一张图和时间，避免同图连发。
- 图没匹配/发送失败 → 继续走文字；日志写清原因。

### 3. `src/platform/douyin/duty-server.mjs`

- `stickerForArgs` 用 `buildStickerQuery` + `pickStickerCandidate`；`stickerQuery` 匹配失败返回可回退信息，不再直接终止。
- `commentStickerQuery` 去掉评论区前 5 条，只保留「自己的回复 + 被回复的评论/视频文案」。
- `tSay` 调整顺序：先成人话 → 再选图 → 再选面板表情 → 最后决定文字 emoji。
  - `stickerQuery` 没匹配 → 若评论可带面板表情，按回复文本情绪自动退面板表情；再不行纯文字。
  - `stickerId` 明确不存在 → 仍报错，要求重新找。
  - `emoji` 支持面板名称或意图名（`laugh/agree/thanks/comfort/tease/surprise/sad/angry/greeting/auto`）；`auto` 按回复文本情绪选，没情绪就不带。
  - 返回 `expression`、`fallback`、`emojiReason`，方便模型知道发生了什么。
- `tFindSticker` 返回 `recommendedId`、`ambiguous`、`fallback`、建议面板表情；不再只给 5 个候选让模型盲选。
- `tDmSend` 增加可选 `stickerId` / `stickerQuery`：
  - 有图：先发文字（最多 1 条气泡），再发图；只过一次频控、只记一次。
  - 图没匹配：自动只发文字，返回 `stickerFallback`。
  - 图发失败但文字已发：返回 `partial=true`，不重复发文字。
- 工具描述同步改成「先文字/短社交 → 图 → 面板 → 文字」的顺序。

### 4. `prompts/douyin-duty.md`

把「带图说话」「面板表情」「主动私信」三节改成一条完整决策链：

1. 先判断内容型还是短社交。
2. 短社交先找自己的图，查询词用「你准备回的那句话」。
3. 图不匹配 → 评论面板表情（按情绪，不默认微笑）→ 文字。
4. 一条最多一个表达层；不每条都带；同一张图不连着发。
5. 主动私信文字为主，图作为附加层；不为了发图单独再发一条。

## 四、不在本轮范围

- 不实现抖音私信面板表情的 DOM 点击（当前只验证了评论面板；私信 Web 端是否有面板、选择器是什么，需要现场实测）。本轮私信只用文字 emoji 兜底。
- 不实现回评论的面板表情（`replyToComment` 当前没有 emoji 参数；需要单独验证回复编辑器是否有同一个表情入口）。
- 不改表情包图义生成流程，不改索引格式，不重新标语义。
- 不改主动私信 10 分钟 / 每小时 2 条的硬频控，只把「文字 + 图」合并成一次。
- 默认仍禁止自动 commit；本轮是负责人明确点名「整体提交并推送」，不改变以后先审查的规则。

## 五、验收标准

- 内容型私信/评论不会被一张语义勉强沾边的图顶掉。
- 短社交回复在语义匹配足够稳时能用自定义表情包；匹配不到会先退面板表情，再退文字。
- 面板表情不会默认「微笑」，也不会每条都带。
- 评论查询不再被评论区噪音带偏。
- 主动私信文字 + 图只消耗一次频控，图失败不会重复发文字。
- 四类链路的行为可以从日志/返回值里看出来：用了哪一层、为什么回退。
